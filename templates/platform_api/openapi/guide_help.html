Ayuda — Paths canónicos

Mapa de rutas HTTP de la API de jobs. No es el contrato (kinds, wait, envelope) ni dispara runners.

Contrato ← Volver a Paths

Para qué sirve esta página

Congela prefijo, método y path para que integradores y módulos no inventen URLs distintas. Prefijo: {{ catalog.prefix }}. Versión: {{ catalog.api_version }}. La fuente viva para la máquina es GET {{ catalog.path_map.openapi }} (Bearer).

Hay un solo POST de ejecución: POST {{ catalog.path_map.run }}. No existe /file-gate/run, /dms/run, etc. El kind va en el cuerpo, no en la URL.

Quién

QuiénQué hace
US Usa esta guía para decirle al integrador qué URL pegar. No se editan paths aquí.
Máquina Auth {{ catalog.auth }}. En run, si reintenta, manda también {{ catalog.idempotency_header }}.
UF No llama estas URLs. Ejecuta en la app; el job_id de esa app es el de GET …/jobs/{job_id} (una tabla u otra según el kind, mismo path).

Qué no está (a propósito)

ÍtemPor qué
GET {{ catalog.path_map.ops_summary }} Fuera del MVP. El pulso de corridas está en el tablero de File Pipeline.
YAML OpenAPI 3 Aplazado (yaml_deferred={{ catalog.yaml_deferred }}). Tampoco hay componentes reutilizables {{ catalog.reusable_components_deferred|join:", " }}. Este índice JSON es la fuente de rutas.
SDK / CRUD de proyectos No van en esta API. Proyectos y billing tienen UI humana.

Errores y artifacts

  • Ítems de error: mismos que el contrato (row, field, code, message).
  • Informe y salida: URL firmada de /report y /output. No arme rutas de disco ni de media/.
  • Un job_id de otra compañía se responde como no encontrado (opaco).

Qué no es esta pantalla

  • No explica kinds ni wait — eso es Contrato.
  • No lista runners por app — eso es Integración.
  • No crea keys — eso es Clientes.
  • No se “publica” un OpenAPI editando esta página; el índice sale del código.
