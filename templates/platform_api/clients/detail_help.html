Para qué sirve esta página

Ficha del cliente {{ client.code }} ({{ client.get_environment_display }}). Es el lugar para ajustar qué puede hacer la máquina y, si hace falta, avisarle a un sistema externo cuando un job termina. No es la pantalla de alta: el Bearer ya se emitió (o se emitirá al rotar). Aquí solo verá una pista (…{{ client.key_hint }}), no el secreto.

Hay dos formularios independientes si el cliente está activo: Guardar configuración (código, nombre, descripción, scopes) y Guardar webhook (callback HTTPS). Guardar uno no envía el otro.

Quién: US de esta compañía. Un cliente revocado es de solo lectura: no hay formularios ni rotar.

Cabecera (identidad)

El subtítulo bajo el código resume el estado de la máquina. No se edita ahí; es informativo.

Qué veFunción
Título (código) Identificador estable del cliente. Se puede cambiar en el formulario; debe seguir único en la compañía.
Entorno (Sandbox / Producción) Se eligió al crear el cliente. Prefija la key (dw_test_ o dw_live_). No se cambia en esta ficha: para otro entorno cree otro cliente.
Activo / Revocado Activo: el Bearer actual puede autenticar. Revocado: ninguna key de este cliente sirve; la ficha queda de consulta.
Último uso Fecha/hora de la última petición HTTP autenticada con esta key. Vacío = aún no ha llamado a la API (o no se ha registrado uso).
Pista …{{ client.key_hint }} Últimos caracteres del secreto, para reconocer qué key está en el cofre del integrador sin volver a mostrarla.

Configuración (la key no cambia)

Primer panel, botón Guardar configuración. Sirve para documentación y permisos. Guardar aquí no rota el Bearer ni toca el webhook.

CampoObligatorioFunción
Código Sí Identificador técnico en listados y auditoría. Minúsculas, números y guiones; único por compañía. Cambiarlo no invalida la key.
Uso / nombre No Etiqueta corta para humanos (quién consume: ERP, RPA…). No autoriza nada.
Descripción Sí Para qué existe esta API: sistema, proceso, horario, responsable. Máx. 2000 caracteres. Tampoco autoriza: eso son los scopes.

Scopes (permisos de la máquina)

Cada casilla es un permiso HTTP. Se aplican en la siguiente llamada; no hay que emitir key nueva. Marque solo lo que el integrador necesita. No es un token de administrador de compañía.

ScopeQué permiteSi no está marcado
jobs:run Disparar un job suelto (POST /api/v1/jobs/run) con un kind (Gate, Pipe, Match, etc.). No puede ejecutar jobs sueltos (sí podría ejecutar pipeline si tiene pipeline:run).
jobs:read Consultar listado y detalle (GET /api/v1/jobs, GET /api/v1/jobs/{id}). Es el polling: saber si el job terminó. No puede preguntar el estado del job por HTTP.
jobs:cancel Cancelar un job aún cancelable (POST /api/v1/jobs/{id}/cancel). En la práctica aplica a jobs DMS en cola y a pipeline no terminal. Cancel devuelve error de permiso o no aplicable.
pipeline:run Disparar un pipeline publicado (kind=file_pipeline o atajo POST /api/v1/pipelines/{id}/runs). No puede orquestar cadenas; sí jobs sueltos si tiene jobs:run.
artifacts:download Bajar informe o archivo de salida (GET …/report, GET …/output) con Bearer. Sin este scope aún puede leer metadatos si tiene jobs:read; los bytes piden este scope o un token firmado en la URL. Metadatos sí (con read); descarga 403/404 según el caso.

Webhook (aviso al terminar el job)

Segundo panel, botón Guardar webhook. Optional. DynamicWorkspace hace POST HTTPS a su sistema cuando el job llega a un estado que usted suscribió. El cuerpo no lleva el archivo: lleva ids, estado y enlaces; el integrador descarga con GET autenticado. No es obligatorio: sin webhook el cliente sigue haciendo polling a GET /api/v1/jobs/{id}.

CampoFunción
Cofre HMAC (una vez) Si acaba de generar o rotar el secreto, aparece el valor en claro una sola vez. Cópielo al integrador. Después solo verá una pista …xxxx.
Pista del secreto Últimos caracteres del HMAC, para reconocer el secreto en el cofre sin revelarlo.
URL de callback (HTTPS) Dónde recibe el POST. Debe ser HTTPS. El host tiene que estar en la lista blanca de Seguridad API. Si no está permitido, el guardado falla (no se envía a un dominio arbitrario: evita SSRF).
Webhook activo Enciende o apaga el envío. Puede dejar URL y eventos guardados y desactivar el disparo sin borrar la configuración.
job.completed Avisar cuando el job termina bien (o con el criterio de «completado» del kind).
job.failed Avisar cuando el job falla.
job.cancelled Avisar cuando el job se cancela.
Secreto HMAC Si lo deja vacío al guardar, el sistema genera uno (y lo muestra una vez si es nuevo). Si pega un valor, usa ese. El integrador valida la firma del POST con este secreto (no es el Bearer de la API).
Rotar secreto HMAC ahora Marque y guarde webhook para invalidar el HMAC anterior y emitir uno nuevo (pantalla de un solo uso). Las peticiones API con Bearer no cambian.

Firma: el receptor debe comprobar HMAC en el header de la petición. Sin secreto válido, un tercero podría fingir callbacks. Reintentos: si su URL no responde 2xx, la plataforma reintenta (vea intentos en la tabla de entregas).

Entregas recientes

Solo aparece si ya hubo intentos de callback. Es el log de este cliente hacia su URL, no el historial del job en Gate/Pipe.

Si el cliente está revocado

No hay formularios ni rotar. Verá la descripción (si existía) y la fecha de revocación. Para una key nueva: Nuevo cliente en el listado, o use otro cliente que siga activo y rótelo allí.

Comprobar que la key del cofre sigue viva

Con el Bearer (no con el HMAC del webhook):

GET /api/v1/whoami
Authorization: Bearer dw_test_… (o dw_live_…)

Debe devolver el código de este cliente y la compañía. Solo exige un Bearer válido (cualquier scope). Ejecutar un archivo es POST /api/v1/jobs/run (otro paso: proyecto publicado + kind).
