Para qué sirve esta página

Es la referencia de forma para todas las llamadas de jobs: qué campos van en el request, cómo se espera (wait), qué estados de máquina existen y cómo se lee el JSON de respuesta. Gate, Pipe y el resto de kinds cambian el archivo y el summary; el envelope no.

No ejecuta nada. Disparar un runner es POST {{ catalog.paths.run|default:"/api/v1/jobs/run" }} (módulo 3). Aquí solo se documenta y se valida la forma.

Dos ejes (no mezclar)

EjeCamposSignificado
Qué kind + project_slug Job suelto de un proyecto publicado (Gate, Pipe, …).
Qué (cadena) kind=file_pipeline + pipeline_id Corrida de pipeline publicado. No ponga también project_slug.
Espera wait=sync | async sync: HTTP 200 cuando termina. async: HTTP 202 y luego consulta el job. Default de pipeline: async.

Atajo: mode=pipeline equivale a kind=file_pipeline.

HTTP de protocolo vs negocio

SituaciónHTTPQué verá el integrador
Request mal formado (kind, wait, destino mezclado, archivo faltante) 400 ok: false y errors[] con row, field, code, message.
Sin versión publicada / pipeline inactivo (en el run) 409 No se crea job. Corrija publicación en la app, no el JSON.
Gate rechaza el archivo (negocio) 200 ok: false, status: completed, veredicto {% for s in catalog.gate_verdict %}{{ s }}{% if not forloop.last %} / {% endif %}{% endfor %}. No es un error de protocolo.
Pipe termina con filas rechazadas 200 Igual: máquina completed; el detalle va en summary y errors[].

Qué no es esta pantalla
