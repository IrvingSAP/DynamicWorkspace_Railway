Ayuda — Borrador de estructura

Congela el patrón detectado y los campos confirmados en una versión exportable. No publica el destino.

← Volver a borrador

Para qué sirve

Detectar y Campos son propuestas que usted confirma. Este paso congela ese estado en un snapshot versionado (bloque source listo para sembrar). Sin borrador no hay Aplicar a FILE GATE o Reverse.

Aquí no se edita la tabla de campos. Si hay que cambiar un nombre, tipo o Inicio/Fin/Long. (TXT posicional), vuelva a Campos y luego guarde una versión nueva.

Prerrequisito

Hace falta campos confirmados. Si no, verá el aviso y un atajo a Campos. El stepper marca Borrador ✓ cuando existe una versión current.

Qué entra en el snapshot

  • Patrón confirmado (tipo, encoding, delimitador, encabezado).
  • Campos: nombre interno, tipo, obligatoriedad; en txt_fixed, posiciones/longitudes.
  • Referencia a la muestra (nombre y hash) para auditar de qué archivo salió.

Siguiente en el ciclo

  1. Aplicar — siembra este borrador en un proyecto FILE GATE o Reverse de la misma compañía.
  2. En el destino, revise el esquema y publique allí. Scout nunca auto-publica.
  3. El timeline completo (borradores + applies) está en Historial.

Roles

  • PA / ED guardan nuevas versiones.
  • GE / CO ven el hub y pueden exportar (CO sin ejemplos de celdas). GE no guarda ni aplica.

Qué no hace este módulo

  • No edita campos ni el patrón de detección.
  • No valida un archivo de producción.
  • No publica FILE GATE ni Reverse ni siembra el destino (eso es Aplicar).
