Ayuda — Historial

Bitácora de versiones de borrador y semillas aplicadas a destinos. Solo lectura: no deshace ni re-aplica.

← Volver al historial

Para qué sirve

Une en una sola línea de tiempo lo que se congeló (cada guardado de borrador) y lo que se sembró (cada apply a un destino: OK o fallido). Sirve para auditar quién, cuándo y qué versión se usó — no para ejecutar producción.

No es el historial de validaciones FILE GATE ni de conciliaciones FILE MATCH. Scout propone estructura; la publicación del contrato o planilla ocurre en el destino.

Cómo se llena

Cada vez que guarda un borrador o aplica a un destino aparece un evento aquí. Si aún no hay ninguno, verá el vacío con atajos a Muestra o Borrador. El stepper marca Historial cuando ya existe al menos un evento.

Detalle de un borrador

  • Metadatos de esa versión: fecha, muestra, hash corto, notas, chips de patrón, conteo de campos.
  • Exportar JSON descarga esa versión (no solo la current). Consulta (CO) no incluye ejemplos de celdas.
  • Ir al hub borrador lleva a la versión actual (no edita el snapshot histórico).
  • Si hay current, puede ir a Aplicar a destino (siembra la current, no necesariamente la versión que está viendo).
  • Eliminar (solo si usted creó el registro): quita esa versión del historial. Si era current, la versión anterior pasa a ser la actual. No deshace destinos ya sembrados.

Detalle de un apply

  • Estado, destino (slug y nombre), tipo de proyecto, versión de draft sembrada y mensaje.
  • Abrir destino solo si el proyecto sigue activo; si está archivado verá el slug histórico sin enlace.
  • Puede abrir el detalle del borrador vN usado en esa siembra.
  • Aplicar de nuevo vuelve al hub Aplicar (otra siembra; no es un deshacer).
  • Eliminar (solo si usted creó el apply): borra la auditoría. No revierte la siembra en GATE, Match, FilePipe, etc.

Roles

  • PA / ED / GE / CO ven el listado y los detalles (metadatos).
  • Eliminar un registro: solo el usuario que lo creó (mismo criterio que FILE GATE).
  • CO: sin ejemplos de celdas en el detalle de draft ni en el JSON exportado.
  • Exportar JSON sigue la misma política que en Borrador (CO restringido).

Qué no hace este módulo

  • No guarda borradores ni aplica a destinos: eso es Borrador y Aplicar.
  • No re-aplica desde la fila ni hace rollback en el destino. Eliminar un apply solo quita el registro de auditoría.
  • No compara campo a campo dos versiones ni filtra por rango de fechas.
  • No lista validaciones de producción, conciliaciones Match ni ejecuciones FilePipe.
