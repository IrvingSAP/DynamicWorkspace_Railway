Ayuda — Origen de la bandeja

Un solo adaptador por bandeja. Al elegir el tipo, se despliega un panel distinto (SFTP, carpeta o API). El resto de campos se oculta.

← Volver al origen

Propósito de la página

Define de dónde llega el archivo a {{ watch.slug }}. No copia a storage (Intake) ni dispara Job (Disparo). Guardar no cambia el estado de la bandeja (En proceso / Activo / Inactivo).

  • Hay un tipo de origen activo. Cambiar de tipo reconfigura el adaptador; los lotes ya ingeridos no se borran.
  • Al pulsar SFTP, Carpeta gestionada o API / webhook, el formulario muestra solo los campos de ese tipo.
  • SFTP y carpeta usan poll del worker. API push espera que un cliente empuje el archivo al endpoint de la bandeja.
  • Activar o reanudar exige origen completo y válido (junto con Disparo y, si dispara al llegar, Enrutado).

El worker lista un directorio remoto a intervalos. Aparece el panel SFTP (host, puerto, usuario, secreto, ruta, poll y qué hacer tras el intake).

CampoObligatorioFunciónValores
Host Sí Servidor SFTP a consultar. Hostname o IP. Ej. sftp.banco.local
Puerto Sí Puerto TCP del servicio. 1–65535. Por defecto 22
Usuario Sí Cuenta remota del listado. Texto. Ej. dw-watch
Contraseña / clave Sí (la primera vez) Se guarda como referencia en el almacén de secretos. No se vuelve a mostrar. Si ya hay secreto, puede dejarlo vacío para no rotarlo. Password o clave. Placeholder •••• si ya existe
Ruta remota Sí Directorio que el monitor lista. Absoluta o relativa al home. Ej. /inbox/extractos
Poll (segundos) Sí Cada cuánto el worker vuelve a listar. Entero ≥ 30. Por defecto 60
Tras intake Sí Qué hacer en el origen después de que Intake confirme el lote. Dejar · Marcar · Borrar remoto
Última prueba — Resultado de «Probar SFTP» (PA/ED). OK · falló · vacío si aún no se probó

Las opciones de «Tras intake» no son las mismas que en SFTP: aquí no hay «Marcar» ni «Borrar remoto»; hay «Mover a procesados» y «Borrar».
