Ayuda — Solape e idempotencia

Qué ocurre cuando un tick nuevo coincide con un run que aún está vivo, y cómo evitar duplicados en el mismo slot.

← Formulario

Propósito

Define qué hace el sistema cuando el tick anterior aún no terminó y llega el siguiente slot. No define el reloj (Programación, M2) ni el destino (M3). Guardar no cambia el estado del plan. Solo PA y ED pueden guardar.

Idempotencia de ventana

La clave única es plan + scheduled_for. El worker nunca crea dos ticks para el mismo slot. Esto no es configurable: es una regla fija del sistema.

ConceptoDetalle
Mismo slot Si el cron dispara las 02:00 y ya existe un tick para esa fecha-hora, el worker lo ignora. No importa cuántas veces corra el comando.
Slots distintos Las 02:00 de ayer y las 02:00 de hoy son dos ventanas. El solape pregunta si el Job de ayer sigue vivo cuando llega el de hoy.
Reintento Un reintento genera un run nuevo con su propio Job. No reescribe ni reemplaza el tick original.

Política de solape

Al guardar se elige una sola política. Define el comportamiento cuando llega un tick nuevo y el run del slot anterior aún tiene estado queued o running.

PolíticaSi el run anterior viveCuándo usarla
Omitir (default) No encola. Tick queda como Omitido (schedule_overlap_skip). Procesos de cierre donde no tiene sentido duplicar: el de ayer debe terminar antes de correr el de hoy.
Encolar detrás Encola el nuevo tick normalmente. Puede haber varios runs simultáneos del mismo plan. Carga de archivos independientes donde cada tick opera sobre un archivo distinto y no hay conflicto.
Cancelar el anterior Aborta el Job/pipeline vivo y encola el nuevo. No borra el plan ni los ticks históricos. Reproceso donde solo importa la versión más reciente del archivo y el anterior ya no sirve.

Comportamiento con otros estados

SituaciónQué pasa
Tick anterior Falló No bloquea. Un tick fallido no es un run «vivo»; el nuevo slot se encola normalmente con cualquier política.
Tick anterior Omitido No bloquea. Un tick omitido no tiene run asociado.
Plan Pausado No genera ticks nuevos. Un run que ya estaba en curso sigue ejecutándose; pausar no cancela Jobs activos.
Plan Archivado No genera ticks. No se puede reanudar; es una baja lógica.

Errores frecuentes

MensajeQué hacer
Tick omitido por solapeEsperado: la política es «Omitir» y el run anterior aún corre. Revise el historial de Actividad para confirmar.
Varios runs simultáneosEsperado si la política es «Encolar detrás». Si no lo desea, cambie a «Omitir».
Run cancelado inesperadamenteLa política es «Cancelar el anterior». Cambie a «Omitir» o «Encolar detrás» si necesita que los runs anteriores terminen.

Permisos y al guardar

Solo PA (propietario) y ED (editor) del plan pueden guardar la política. US de la compañía puede ver la configuración pero no modificarla.

Guardar registra schedule.updated. Si el plan ya está Activo, el próximo tick usa la nueva política; no afecta un Job ya encolado o en curso. Cambiar la política no cambia el estado del plan (no lo activa ni lo pausa).
