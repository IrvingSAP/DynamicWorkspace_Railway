Ayuda — Dependencia

Encadenar dos planes existentes: el hijo se encola cuando el padre termina. No sustituye el diseñador de File Pipeline.

← Formulario

Propósito

Define si este plan se dispara por reloj (Programación, M2) o por la finalización de otro plan (padre). Ambos modos son mutuamente excluyentes: un plan solo tiene un disparador. Guardar no cambia el estado del plan. Solo PA y ED pueden guardar.

Reloj vs. dependencia

Al elegir Dependencia, el worker de cron deja de evaluar este plan. El tick se crea únicamente cuando el run del padre alcanza el estado configurado en la condición.

DisparadorCuándo se encolaRequisito para Activar
Reloj (cron) En cada slot que coincida con la expresión cron de Programación (M2). Destino (M3) configurado + Programación (M2) guardada.
Dependencia (padre) Cuando el run del plan padre alcanza la condición elegida. Destino (M3) configurado + padre válido + condición seleccionada.

Padre válido

ReglaDetalle
Mismo plan Prohibido. Un plan no puede ser padre de sí mismo.
Mismo destino Prohibido. El padre no puede apuntar al mismo proyecto/pipeline que este plan.
Plan archivado No seleccionable. Solo aparecen planes activos o pausados de la misma compañía.
Cadena circular Prohibido. Si A depende de B, B no puede depender de A (ni indirectamente).

Condición de disparo

Define qué estado terminal del run padre activa el tick de este plan.

CondiciónDispara si el padre…Cuándo usarla
Éxito Terminó OK (completed). Caso típico: el hijo solo procesa si el padre fue exitoso.
Aceptado Solo File Gate con veredicto accepted. El hijo procesa solo archivos que pasaron validación Gate.
Cualquier terminal Incluye fallo y rechazo. No recomendado. Útil solo para alertas o auditoría que deben correr siempre.

Comportamiento del tick delegado

ConceptoDetalle
Origen del tick El run delegado lleva trigger_source=dependency y referencia al parent_job_id.
Entrada del hijo Sigue siendo la configurada en Destino (M3) de este plan (Artifact, Watch o sin archivo). No hereda automáticamente la salida del padre.
Idempotencia El mismo run padre no dispara dos veces al mismo hijo. Si el padre se reintenta y vuelve a completar, genera un nuevo tick.
Solape Si el hijo ya tiene un run vivo, la política de Solape (M5) de este plan aplica normalmente.

Errores frecuentes

MensajeQué hacer
Seleccione un plan padreEligió Dependencia pero no seleccionó un padre. Elija un plan de la lista o cambie a Reloj.
El padre no puede ser el mismo planSeleccionó este plan como padre. Elija otro plan.
Dependencia circular detectadaEl padre (o un ancestro) ya depende de este plan. Reorganice la cadena.
Tick no generado (padre sin run)El padre no ha completado ningún run desde que se activó la dependencia. Verifique que el padre esté activo y ejecutándose.

Permisos y al guardar

Solo PA (propietario) y ED (editor) del plan pueden guardar. US de la compañía puede ver la configuración pero no modificarla.

Guardar registra schedule.updated. Si el plan ya está Activo, el siguiente evento del padre usa la nueva configuración; no afecta un tick ya encolado. Cambiar de Dependencia a Reloj (o viceversa) no cambia el estado del plan.
