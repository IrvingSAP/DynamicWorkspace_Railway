Ayuda — Avisos del plan

Quién recibe correo o webhook cuando un tick falla, un run termina en error o un slot se omite.

← Formulario

Propósito

Configura las notificaciones automáticas del plan. Por defecto los avisos están apagados. Activar el plan no exige esta pantalla; es opcional. Guardar no cambia el estado del plan. Solo PA y ED pueden guardar.

Eventos que generan aviso

Cada evento envía un solo aviso por ocurrencia. No se reenvía el mismo fallo.

EventoCuándo ocurreQué incluye el aviso
Tick fallido El worker no pudo encolar el tick: falta entrada, sin versión publicada, error de cola, etc. Slug del plan, slot programado, código de error (schedule_missing_input, schedule_no_published_target, etc.).
Run fallido El Job o pipeline ya encolado terminó en estado failed. Slug del plan, ID del Job/pipeline, motivo del fallo. El detalle completo está en el historial del run.
Omitido por solape La política de Solape (M5) es «Omitir» y el run anterior aún estaba vivo. Slug del plan, slot omitido, ID del run que bloqueó. Solo avisa si se marca la casilla correspondiente.

Canales de notificación

CanalDetalleLimitaciones
Correo Se envía al email del miembro del plan marcado como destinatario. No incluye filas del archivo ni adjuntos. Solo texto con el resumen del evento.
Webhook POST HTTPS a la URL configurada con payload JSON del evento. Debe ser HTTPS. No es una persona; es un sistema receptor (Slack, Teams, endpoint propio, etc.).

Destinatarios

ReglaDetalle
Solo miembros del plan Los destinatarios se seleccionan de la lista de miembros. Para agregar nuevos, vaya primero a Miembros.
Selección individual Se tildan aquí los miembros que deben recibir avisos. No todos los miembros reciben por defecto.
Webhook independiente El webhook se configura aparte de los miembros. Un plan puede tener correo, webhook o ambos.

Errores frecuentes

MensajeQué hacer
No hay miembros para notificarAgregue miembros al plan en la sección Miembros antes de activar avisos por correo.
URL de webhook inválidaDebe ser una URL HTTPS válida. No se aceptan HTTP ni URLs locales.
No recibí el avisoVerifique que su usuario esté tildado como destinatario y que el evento corresponda a uno de los tipos configurados.

Permisos y al guardar

Solo PA (propietario) y ED (editor) del plan pueden guardar. US de la compañía puede ver la configuración pero no modificarla.

Guardar registra schedule.updated. Si el plan ya está Activo, los avisos aplican desde el siguiente evento; no se envían retroactivamente para ticks o runs anteriores.
