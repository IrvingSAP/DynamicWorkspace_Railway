Cómo funcionan los paths canónicos

Paths es el mapa de método + URL de PLATFORM API. Prefijo único /api/v1, un solo POST de ejecución, Bearer y, en el run, Idempotency-Key. El YAML OpenAPI 3 está aplazado: este índice (pantalla + GET /api/v1/openapi) es la fuente de rutas.

Esta página describe el flujo de lectura para el integrador. El ? de la pantalla Paths es la ayuda contextual de esa tabla.

Ruta rápida

  1. Pegue host + path de la tabla (sin /j/ de más).
  2. Auth: Bearer; en run, header de idempotencia.
  3. El kind va en el cuerpo, no en la URL.

Qué es Paths

El índice canónico de superficie HTTP: whoami, contract, validate, run, detalle, report, output, listado, cancel, atajo de pipeline. No hay /file-gate/run ni un path de run por app.

En una frase

El mapa de direcciones. El contrato dice cómo va el JSON; Paths dice a qué URL pegarlo.

Qué ve US en pantalla

  • Reglas: Bearer, Idempotency-Key, errores como el contrato.
  • Tabla método / path / módulo / fase / si está en código.
  • YAML diferido; GET /ops/summary documentado y no implementado.
2

Cuál es la función de Paths

Función principal: que integradores y módulos no inventen URLs distintas y que el job_id sea el de la app que ejecutó (un path, no un id paralelo de PLATFORM API).

Problema que resuelve

  • Un endpoint “de producto” por silo.
  • Confundir el atajo de pipeline con un segundo producto.
  • Esperar un fichero OpenAPI 3 como única fuente.

Qué ganas

  • Misma tabla en UI y en GET /api/v1/openapi.
  • Atajo POST /pipelines/{id}/runs ≡ run con kind=file_pipeline.
  • Report/output: no adivinar rutas de disco.
3

Qué no es (y qué sí usar en su lugar)

Paths no…

  • No explica kinds, wait ni envelope (eso es Contrato).
  • No emite keys (Clientes).
  • No lista runners Django (Integración).
  • No es un SDK ni un YAML descargable (aún).

Usa otra pantalla si…

  • Contrato — forma del JSON y tabla de kinds.
  • Integración — qué app atiende cada kind.
  • Seguridad — TTL de artifacts y tasa.
4

Reglas al pegar una URL

  • Prefijo http://…/api/v1/… (local: http, no https).
  • Auth: Authorization: Bearer + la key. La cookie US no autentica.
  • Run: form-data + archivo; header Idempotency-Key.
  • {job_id} y {pipeline_id} son del tenant de esa key, sin llaves en la URL real.
5

Flujo de trabajo

whoami → (contract) → run → GET job → report/output, siempre con paths de esta tabla.

  1. US abre Paths y apunta el método que el ERP debe usar.
  2. La máquina confirma el índice: GET /api/v1/openapi.
  3. Arme Postman/curl con el path exacto (detalle sin /report; informe con él).
  4. Si hace falta listar: GET /api/v1/jobs con query, no el UUID en el path.

Casos típicos

  • HTML 404 en /j/api/v1/… — typo; el path canónico no lleva esa j.
  • PowerShell parte /output si la URL va sin comillas.
  • 404 JSON en output con Split de varias partes: el path es correcto; no hay un solo archivo.
  • GET /ops/summary en la tabla con “No (MVP)”: use el tablero de Pipeline, no esa URL.
