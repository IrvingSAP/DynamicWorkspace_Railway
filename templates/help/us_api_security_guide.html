Cómo funciona la política de proceso

Seguridad (en este menú) no es el 2FA de personas. Es la política HTTP de la compañía: tamaño de archivo, solicitudes por minuto, TTL de informe/salida, extensiones y hosts de webhook. La key dice quién entra; esta pantalla dice qué se acepta al procesar.

El runner de Gate o Split no puede saltarse estas reglas. El ? de la pantalla Seguridad es la ayuda de cada campo del formulario.

Ruta rápida

  1. Ajuste MB, rate, TTL y extensiones; Guardar política.
  2. Si usará webhooks, liste hosts HTTPS (sin esquema).
  3. HMAC y eventos: ficha del cliente, no este formulario.

Qué es la política de proceso

Un registro por compañía (ApiProcessPolicy) que la API aplica alrededor del job: upload, rate en whoami/run, tokens de artifact, allowlist anti-SSRF. No se configura por cliente (salvo webhook URL/HMAC en la ficha).

En una frase

Los límites de integridad de la ejecución remota. Auth (Clientes) es otra capa.

Defaults habituales

  • 50 MB, 60 req/min, TTL 24 h.
  • Extensiones tipo intake (.txt .csv .xlsx…).
  • Allowlist de hosts vacía = ningún callback de URL pasa.
2

Cuál es la función

Función principal: que un ERP no suba de más, no dispare a destajo, no descargue artifacts eternos ni apunte webhooks a localhost o IPs privadas. Los logs no guardan cuerpos ni tokens (PII).

Problema que resuelve

  • Intake de la app vs API con reglas distintas.
  • Enlaces de informe que nunca caducan.
  • SSRF si el callback apunta a la red interna.

Qué ganas

  • whoami muestra la política vigente.
  • IDs ajenos: 404 opaco, no “existe en otra compañía”.
  • Artifacts con token firmado + TTL.
3

Qué no es (y qué sí usar)

Esta pantalla no…

  • No rota ni revoca keys (Clientes).
  • No es el login 2FA de US/UF.
  • No configura el secreto HMAC (ficha del cliente / webhooks).
  • No autoriza proyectos: sigue el tenancy y GE del destino.

Usa otra pantalla si…

  • Clientes — identidad y scopes.
  • Auditoría — quién rotó o revocó.
  • Ficha del cliente — URL de webhook y eventos.

Flujo de trabajo

Definir límites → guardar → probar whoami / run (no es el botón Rotar key).

  1. US abre Seguridad y revisa cuotas alineadas al intake de las apps.
  2. Si el banco enviará callbacks, añada el host (p. ej. hooks.banco.example).
  3. Guardar política. whoami refleja max_upload, rate y TTL.
  4. En la ficha del cliente: URL HTTPS de ese host, eventos y secreto HMAC.

Qué no se relaja aquí

  • Solo versión publicada — run sin publicar: 409.
  • Dry-run no suma al pulso del tablero; no hay checkbox.
  • Job o pipeline de otra compañía: 404 opaco.
7

Casos típicos

  • QA con archivos chicos: 50 MB sobra; baje el rate si un script dispara whoami en bucle.
  • Informe 404 al día siguiente: TTL de 24 h cumplido; no es un Bearer malo.
  • Webhook http://… o host no listado: la política bloquea; no es un fallo del HMAC.
