Cómo funciona la integración (UI ↔ API)

Integración es el mapa de qué runner atiende cada kind. PLATFORM API no es un vertical de archivos: no tiene project_kind ni menú UF. Invoca el mismo motor que Gate, Pipe, Match, Clean, Split o Pipeline cuando UF pulsa Ejecutar.

Esta página describe el recorte para el integrador. El ? de la pantalla Integración es la ayuda contextual de esas tablas.

Ruta rápida

  1. Confirme que el kind está cableado (no solo en catálogo).
  2. UF publica el proyecto o pipeline; el slug / pipeline_id van en el run.
  3. Un POST /jobs/run; el historial de la app usa el mismo job_id.
Quién USMuestra al ERP qué kind está vivo MáquinaGET /integration; kind en el body, no un path por app UFDiseña y publica; el job_id es el de su historial WatchMismo runner; otro trigger_source (previsto)

Qué es Integración

El inventario kind → app Django → función runner → fase → cableado. Identidad de producto: PLATFORM_API / apps.platform_api. La máquina lo lee en GET /api/v1/integration.

En una frase

La tabla de despacho: quién ejecuta de verdad cuando llega el HTTP. Contrato y Paths no dicen el nombre del servicio interno.

Qué ve US en pantalla

  • Identidad (app, prefijo, keys US, run único, atajo pipeline).
  • Tabla kinds con runner y Sí/No cableado.
  • Mapeo “Ejecutar en UI” → path HTTP equivalente.
2

Cuál es la función

Función principal: reusar parsers, reglas y jobs de cada app; no duplicar un motor HTTP. Pipeline delega en el orquestador; no hay una segunda cadena.

Problema que resuelve

  • Creer que la API es otra FilePipe o otro historial.
  • Disparar un kind que está en catálogo pero no en el run (Repair, Profiler).
  • Worksheets / records como si fueran jobs de archivo.

Qué ganas

  • Misma evidencia en historial UF y en GET job.
  • Tablero Pipeline ve trigger_source=api.
  • Watch/Scheduler previstos: mismo runner, otro canal.
3

Qué no es (y qué sí usar)

Integración no…

  • No define el envelope JSON (Contrato).
  • No lista cada URL (Paths).
  • No crea keys (Clientes).
  • No publica esquemas: eso sigue en UF.

Usa otra pantalla si…

  • Contrato — kinds, wait, validate.
  • Paths — método y path exactos.
  • Seguridad — cuotas y TTL.

5

Flujo de trabajo

Publicar en UF → comprobar cableado → run con ese kind.

  1. US abre Integración y confirma “Sí” en el kind del ERP.
  2. UF deja versión publicada (proyecto o pipeline active).
  3. Máquina: Bearer, kind, slug o pipeline_id, archivo(s), Idempotency-Key.
  4. Revise el historial de esa app (Split ≠ Gate) con el mismo UUID.
