Jobs sueltos por HTTP

Para quien nunca ha disparado DynamicWorkspace por API. Las pantallas de Gate, Pipe o Split diseñan el trabajo; aquí se identifica la máquina y se dispara el mismo job publicado.

Un paso cada vez. Los recuadros de comando son la misma petición en desarrollo y en producción: cambia el host, la key y, en Windows, el binario curl.exe. No pegue keys en chats. El circuito de cadenas publicadas está en Pipelines.

Antes de la primera llamada

Compañía activa, usuario US (no UF), 2FA si aplica, y un proyecto publicado (cualquier kind cableado: Gate, Split, Clean…). El slug es el de UF, no un UUID de API.

Abrir Clientes de máquina →

E

Desarrollo vs producción

Los paths no cambian: siempre /api/v1/… (whoami, validate, run, jobs/{job_id}, report, output, cancel). Lo que cambia es dónde vive el servidor y qué cliente usa (sandbox o producción). No mezcle una key dw_test_ contra el host de prod, ni al revés.

Base de esta instancia (la que está leyendo ahora): {{ request.scheme }}://{{ request.get_host }}

Desarrollo (local)

  • URL base: http://127.0.0.1:8000 (o el puerto de runserver).
  • Cliente: entorno Sandbox. Key dw_test_….
  • Windows PowerShell: curl.exe (no el alias curl).
  • Linux/macOS o Git Bash: curl (mismos flags).
  • Postman: {% verbatim %}{{base}}{% endverbatim %} = esa URL local, sin barra final.

Producción (desplegado)

  • URL base: https:// + el dominio del servidor (nunca 127.0.0.1 salvo túnel).
  • Cliente: entorno Producción (otro cliente). Key dw_live_….
  • Desde un PC Windows hacia prod: sigue valiendo curl.exe con esa base HTTPS.
  • Desde Linux, CI o el ERP: curl o el cliente HTTP del lenguaje; mismos headers y -F.
  • Postman: otro environment (o cambie base y key).

En los recuadros siguientes, {% verbatim %}{{base}}{% endverbatim %} es esa URL (sin /api). Sustituya dw_test_… por la key del cliente de ese entorno. El project_slug es el publicado en esa compañía.

P

Postman = la misma API que curl

El navegador no manda Bearer al pegar una URL. En el environment, base es el host (local o HTTPS de prod, sin barra final) y key es el secret sin la palabra Bearer. Authorization → Bearer Token → {% verbatim %}{{key}}{% endverbatim %}. Dos environments (dev / prod) evitan pegar la key sandbox contra el dominio real.

GET (whoami, contract, job)

Body none. No cree el header Authorization a mano si ya usa la pestaña Auth.

POST run / validate

Body form-data. El archivo va como tipo File, no raw JSON. Run: header Idempotency-Key.

1

Entrar como US y abrir API

PLATFORM API no está en el menú de archivos UF. Usted entra a la consola; el ERP usará el Bearer después.

  1. Inicie sesión US (correo / TOTP si aplica).
  2. Menú API → Clientes de máquina.
  3. Debe ver /app/platform-api/clientes/.

Si no aparece API: no es perfil US. No haga curl todavía: no hay key.

2

Crear el cliente y copiar la key

Un cliente = una identidad estable. La key se muestra una vez (alta o rotar). Copie al cofre; no recargue Key emitida.

  1. + Nuevo cliente: código, sandbox o producción, scopes.
  2. Scopes mínimos de prueba: jobs:run, jobs:read, artifacts:download. Cancel y pipeline si los va a usar.
  3. Sandbox: prefijo dw_test_. Producción: otro cliente.
3

Contrato, Paths e Integración

Lea las tres pantallas (y sus ?). No ejecutan jobs. Confirme que su kind está cableado y el path de run es uno solo.

4

Política de seguridad

Tamaño, rate, TTL, extensiones. whoami devolverá esos números. Guardar política no es Rotar key.

5

Proyecto publicado

En UF, anote el project_slug. Sin versión publicada el run responde 409. Un Split de varias partes no tendrá un solo output_url.

6

whoami, validate y contract

Primera prueba de Bearer. Validate no ejecuta el motor. Contract lista kinds.

Plantilla para ambos entornos. En desarrollo, {% verbatim %}{{base}}{% endverbatim %} = http://127.0.0.1:8000 y key dw_test_. En producción, https://su-dominio y key dw_live_. Windows PowerShell: curl.exe. Linux/CI: el mismo comando con curl.

curl.exe -sS -H "Authorization: Bearer dw_test_…" "{% verbatim %}{{base}}{% endverbatim %}/api/v1/whoami"
curl.exe -sS -H "Authorization: Bearer dw_test_…" -F "kind=file_split" -F "project_slug=su-slug" -F "wait=sync" "{% verbatim %}{{base}}{% endverbatim %}/api/v1/jobs/validate"
curl.exe -sS -H "Authorization: Bearer dw_test_…" "{% verbatim %}{{base}}{% endverbatim %}/api/v1/contract"

200 + ok: true. 401: key mal pegada o Bearer duplicado en Postman. URL sin /j/ extra.

7

Ejecutar (POST /jobs/run)

Sí corre el runner. Misma Idempotency-Key + mismo archivo = replay (mismo job_id). Key nueva = otro job.

curl.exe -sS -H "Authorization: Bearer dw_test_…" -H "Idempotency-Key: su-clave-unica" -F "kind=file_split" -F "project_slug=su-slug" -F "wait=sync" -F "file=@archivo.txt" "{% verbatim %}{{base}}{% endverbatim %}/api/v1/jobs/run"

Anote el job_id. No escriba la palabra GET/POST en PowerShell.

8

Detalle, informe, salida, listado

A = envelope. B = manifiesto (no tiene ok/job_id). C = un archivo de negocio; Split de N partes → 404 JSON «El artifact no está disponible.» D = listado de compañía.

curl.exe -sS -H "Authorization: Bearer dw_test_…" "{% verbatim %}{{base}}{% endverbatim %}/api/v1/jobs/{job_id}"
curl.exe -sS -L -H "Authorization: Bearer dw_test_…" --output informe.bin "{% verbatim %}{{base}}{% endverbatim %}/api/v1/jobs/{job_id}/report"
curl.exe -sS -L -H "Authorization: Bearer dw_test_…" --output salida.bin "{% verbatim %}{{base}}{% endverbatim %}/api/v1/jobs/{job_id}/output"

URL entre comillas y --output (no -o) para que PowerShell no recorte /output. Listado: Params kind y limit, path sin UUID.

9

Auditoría US vs historial UF

Menú Auditoría = ciclo de vida de la key. El JSON del job trae audit del disparo HTTP. Las partes de un Split se ven en el historial de File Split/Merge, no en /output.

10

Rotar, cancelar, revocar

  1. Rotar (no es Guardar configuración) → Key emitida → whoami con la vieja = 401 invalid_token; con la nueva = 200, mismo client_code.
  2. Cancelar un Split ya completed = 409 cancel_not_allowed. El historial no se borra. Marque jobs:cancel si falta.
  3. Revocar cierra el sandbox. whoami = 401. No hay des-revocar: otro cliente. Los jobs corridos permanecen.
curl.exe -sS -X POST -H "Authorization: Bearer dw_test_…" "{% verbatim %}{{base}}{% endverbatim %}/api/v1/jobs/{job_id}/cancel"
!
