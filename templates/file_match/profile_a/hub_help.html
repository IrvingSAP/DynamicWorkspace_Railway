Ayuda — Perfil A

Cómo debe leerse el archivo A (origen de referencia / lado izquierdo). No define el archivo B ni publica la definición.

← Volver al hub

Qué es este hub

Es el Módulo 1 del Conciliador: el asistente que describe el archivo A (extracto, origen de referencia). El resultado es un perfil versionable (forma SourceProfile) en el borrador del proyecto.

  • Copy correcto: “Archivo A” / “Lado A” / “Perfil A”. No es “planilla de emisión” (Reverse), “contrato de validación” (FILE GATE) ni “origen para transformar” (FilePipe).
  • La edición ocurre siempre en el borrador de la versión.
  • En el hub ve progreso (pasos hechos), tipo de archivo, conteo de campos y el listado del asistente.

Los 6 pasos del asistente

#PasoPara qué sirve
1 Tipo de archivo A Formato, encoding y fin de línea. Condiciona la pantalla de campos (paso 4).
2 Inicio de captura Dónde empieza a leerse el contenido útil del archivo A.
3 Fin de captura Dónde termina la captura (cola, marcador, etc.).
4 Campos del archivo A Columnas/campos con name estable. Alimentan las claves del Módulo 3.
5 Reglas de contenido Reglas globales al leer A (p. ej. filas vacías, validaciones de contenido).
6 Informe de lectura Qué reportar al parsear A en el job de conciliación.

Estados en el hub: Completo / En edición / Pendiente. Cada paso tiene su propia ayuda contextual.

Tipos de archivo permitidos (MVP)

CódigoUso típico
csvExtractos delimitados por coma (caso frecuente).
xlsxHojas Excel.
txt_delimitedTXT con delimitador (p. ej. pipe o tab).
txt_fixedTXT posicional (libros / legados).
jsonJSON (si el parser está activo en el tenant).
xmlXML (si el parser está activo en el tenant).

La UI solo ofrece esta whitelist; un tipo fuera de lista se rechaza al guardar. Si cambia el tipo con campos ya definidos, revise el paso 4: la estructura anterior puede quedar inválida.

Importar estructura (PROFILE SEED)

  • Si ya modeló el layout en FILE GATE u otro Match, puede Importar estructura al borrador A (solo PA/ED).
  • Copia un perfil/contrato publicado; no publica Match ni abre el bridge FILE GATE.
  • No sustituye a STRUCTURE SCOUT (eso parte de una muestra de archivo).
  • Use ¿Qué es esto? en el panel del hub o el historial de importaciones para más detalle.

Orden de trabajo recomendado

  1. Complete los 6 pasos del Perfil A (o importe estructura y revise).
  2. Continúe a Perfil B (Módulo 2).
  3. Defina Reglas de cruce (Módulo 3) usando los name de A y B.
  4. Publique A + B + reglas juntos (Módulo 4).
  5. Concilie subiendo archivos A y B (Módulo 5).

Regla de producto: completar el Módulo 1 no basta para conciliar. No existe “Publicar solo A”.

Roles

RolEn Perfil A
PA / EDEditan y guardan el borrador; pueden importar estructura.
GE / COConsulta del hub y pasos en solo lectura (sin guardar definición).

Buenas prácticas

  • Los name de campo deben ser únicos y estables: alimentan las claves del Módulo 3.
  • Elija el tipo de archivo que usa el proveedor, no “el más flexible”.
  • Al menos un campo y tipo de archivo A son obligatorios al publicar la definición completa (M4).
  • Guarde borrador al cerrar cada paso; use Continuar edición para retomar el siguiente pendiente.

Qué no hace este módulo

  • No define el Perfil B ni las reglas de cruce.
  • No sube archivos de producción ni ejecuta la conciliación.
  • No publica solo el lado A (publicar es el Módulo 4: A + B + reglas).
  • No configura el bridge FILE GATE ni sustituye STRUCTURE SCOUT.
