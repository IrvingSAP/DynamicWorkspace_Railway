FILE MATCH · Módulo 5 · {{ project.slug }}

Ayuda — Ejecutar conciliación

Suba el archivo A y el archivo B. El cruce usa solo la definición publicada, no el borrador.

← Volver a ejecutar

Para qué sirve

Cada corrida parsea A y B con los perfiles publicados, cruza por la clave 1:1 y produce un veredicto más el informe de diferencias. No valida un único archivo (FILE GATE) ni genera un destino ETL (FilePipe).

Prerrequisitos

  • Debe existir una versión publicada activa. Si no, verá el aviso y el CTA Ir a Publicar.
  • Permiso de ejecución: PA / ED / GE / CG. CO no ejecuta ni descarga filas de negocio.
  • Los archivos deben respetar tipo, extensión y tamaño máximo indicados en las tarjetas de carga.

Qué produce el job

ConceptoDetalle
Lectura A y B Parseo con captura, campos e informe de lectura de cada perfil. Filas rechazadas no entran al cruce.
Cruce 1:1 Clave publicada. Buckets: matched, value_mismatch, only_a, only_b, duplicate_key.
Veredicto Cuadra / no cuadra / parcial según política de reglas y errores fatales de lectura. Detalle en la ayuda del resultado.
Descargas JSON del informe y CSV de diferencias (cruce). El CSV de lecturas es otro artefacto (parseo A/B).

Buenas prácticas

  • Use archivos de producción (o una muestra real), no un CSV “limpio” de laboratorio.
  • Si acaba de cambiar campos o la clave, publique de nuevo antes de conciliar.
  • Un “no cuadra” puede ser parseo (informe de lectura) o cruce (buckets). Revise ambos en el resultado.
  • El historial completo está en el módulo 6; aquí solo las corridas recientes.

Qué no hace este módulo

  • No edita Perfil A/B ni reglas (vuelva al hub / wizards / publicar).
  • No publica la definición.
  • No sustituye la validación FILE GATE; el bridge es un pre-check opcional.
