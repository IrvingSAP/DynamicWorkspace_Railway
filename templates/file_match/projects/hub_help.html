Qué es este hub

Es el punto de entrada del proyecto Conciliador (FILE MATCH). Agrupa perfiles A y B, reglas de cruce, la versión publicada, las conciliaciones (jobs) y el historial. No es FilePipe (no hay archivo destino ETL) ni FILE GATE (no valida un solo archivo de producción).

  • Objetivo: cruzar dos orígenes (A vs B) por clave 1:1 y obtener un informe de diferencias.
  • Strip superior: versión borrador, versión activa publicada y conteo de miembros.
  • Stepper + paneles: avance del ciclo y accesos directos a cada módulo.
  • Miembros: botón visible solo para el administrador (PA).

Fases del ciclo

FaseQué cubreEn el hub
Definición (M1–M4) Perfil A → Perfil B → Reglas → Publicar Primera franja del stepper
Ejecución (M5–M6) Conciliar A+B → Historial / informe Segunda franja del stepper
Integración (M8) Bridge opcional FILE GATE (pre-check) Panel de auditoría; no es paso numerado

Stepper — qué hace cada paso

#PasoPara qué sirveCuándo se activa
1 Perfil A Define cómo se lee el archivo de referencia (tipo, encoding, campos del lado A). Desde el inicio; wizard de 6 pasos.
2 Perfil B Igual para la contraparte (lado B). Tras completar Perfil A.
3 Reglas Clave de cruce 1:1, campos a comparar y normalización. Tras completar Perfil B.
4 Publicar Congela A + B + reglas juntos en una versión activa. Sin publish parcial. Tras reglas listas; queda marcado si ya hay publicada.
5 Conciliar Suba archivos A y B contra la versión publicada; genera el job e informe. Solo si hay versión publicada.
6 Historial Auditoría de jobs, certificados y acceso al informe. Si hay versión publicada.

Paneles del hub

  • Perfil A / B: progreso del wizard y CTA para continuar o abrir.
  • Reglas: conteos de clave / campos a comparar.
  • Publicar: estado de la versión activa y CTA al módulo 4.
  • Ejecutar: acceso a Conciliar (bloqueado hasta publicar).
  • Auditoría e integración: Historial + enlace a Integración FILE GATE (bridge).

Orden de trabajo recomendado

  1. Revise miembros (PA) si otras personas deben editar o ejecutar.
  2. Complete Perfil A (6 pasos) → Perfil B → Reglas.
  3. Publique la definición (A + B + reglas).
  4. (Opcional) Configure el bridge FILE GATE si quiere pre-check de A y/o B.
  5. Concilie subiendo A y B → revise el informe y el historial.

Regla de producto: no se concilia sin versión publicada.

Borrador vs versión publicada

  • Perfil A, Perfil B y reglas se editan en borrador hasta publicar.
  • Al publicar se crea una versión activa; el borrador vuelve a ser editable (copia).
  • Los jobs de conciliación usan solo la versión publicada activa, no el borrador.

Roles (resumen)

RolEn este hub

EDEdita definición, publica y concilia; no gestiona miembros.
GEConcilia y descarga informe; no edita perfiles/reglas ni publica.
COConsulta hub e historial; sin detalle de filas ni descarga de datos de negocio.

Detalle de invitaciones y permisos: pantalla Miembros → Ayuda. Guía de producto: menú FILE MATCH → Ayuda.

Qué no hace este hub

  • No edita campos del perfil ni reglas (eso está en cada módulo del stepper).
  • No sube archivos de conciliación (eso es Conciliar).
  • No publica automáticamente: hay que entrar a Publicar y confirmar.
  • No sustituye FILE GATE ni genera un archivo destino de negocio.
