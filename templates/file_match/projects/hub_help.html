Qué es este hub

Es el punto de entrada del proyecto Conciliador. Agrupa Perfil A, Perfil B, reglas de cruce, la versión publicada, las conciliaciones y el historial. No transforma a un archivo destino (FilePipe) ni valida un único archivo de producción (FILE GATE).

  • Objetivo: cruzar dos orígenes (A vs B) por clave 1:1 y obtener un informe de diferencias.
  • Strip superior: slug, visibilidad, su rol, borrador vs versión activa, miembros.
  • Stepper + paneles: avance del ciclo y accesos a cada módulo.
  • Miembros: botón visible solo para el administrador (PA).

Fases del ciclo

FaseQué cubreEn el hub
Definición (M1–M4) Perfil A → Perfil B → Reglas → Publicar Primera franja del stepper
Ejecución (M5–M6) Conciliar A+B → Historial / informe Segunda franja del stepper
Integración (opcional) Bridge FILE GATE (pre-check de A y/o B) Panel de auditoría; no es paso numerado

Stepper — qué hace cada paso

#PasoPara qué sirveCuándo marca ✓
1 Perfil A Cómo se lee el archivo de referencia (tipo, captura, campos, informe de lectura A). Wizard A de 6 pasos completo, con tipo y al menos un campo.
2 Perfil B Igual para la contraparte. El tipo de B puede diferir del de A. Wizard B completo, con tipo y al menos un campo.
3 Reglas Clave 1:1, campos a comparar y normalización de cruce. Hay clave usable y las reglas pasan validación estricta.
4 Publicar Congela A + B + reglas juntos. Sin publish parcial. Existe una versión publicada activa.
5 Conciliar Suba archivos A y B contra la versión publicada. Hay versión publicada (el enlace se habilita entonces).
6 Historial Jobs, certificados e informe de conciliación. Hay versión publicada (auditoría de corridas).

Paneles y acciones

  • Perfil A / B: progreso del wizard y CTA para continuar o abrir. En B, atajo Copiar desde A si el layout es el mismo.
  • Reglas: conteos de clave / campos a comparar.
  • Publicar: estado de la versión activa; no publica desde el hub: hay que confirmar en el módulo 4.
  • Ejecutar: conciliar (bloqueado hasta publicar).
  • Auditoría e integración: Historial + bridge FILE GATE opcional.

Orden de trabajo recomendado

  1. Revise miembros (PA) si otras personas deben editar o ejecutar.
  2. Complete Perfil A → Perfil B → Reglas.
  3. Publique la definición (A + B + reglas).
  4. (Opcional) Configure el bridge FILE GATE si quiere pre-check de A y/o B.
  5. Concilie subiendo A y B → revise el informe y el historial.

Regla de producto: no se concilia sin versión publicada.

Borrador vs versión publicada

  • Perfil A, Perfil B y reglas se editan en borrador hasta publicar.
  • Al publicar se crea una versión activa; el borrador vuelve a ser editable (copia).
  • Los jobs usan solo la versión publicada activa, no el borrador en edición.

Qué no hace este hub

  • No edita campos del perfil ni reglas (cada módulo del stepper).
  • No sube archivos de conciliación (eso es Conciliar).
  • No publica automáticamente: hay que entrar a Publicar y confirmar.
  • No sustituye FILE GATE ni genera un archivo destino de negocio.
