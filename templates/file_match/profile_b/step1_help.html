Ayuda — Tipo de archivo B

Fija cómo FILE MATCH abre el archivo B (contraparte): formato, bytes y cortes de línea. Condiciona el paso 4 y las extensiones al conciliar.

← Volver al paso 1

Para qué sirve

El tipo declara qué archivo B espera el proveedor, no “el más cómodo de modelar”. Encoding y fin de línea deciden cómo se leen los bytes antes de captura, campos o reglas.

Se guarda en el borrador del Perfil B. Conciliar usa la definición publicada (A + B + reglas, Módulo 4). Este paso no publica solo el lado B.

Qué decide este paso

ElementoEfecto al conciliar
Tipo de archivo Parser del archivo B y extensiones permitidas al subir el lado B.
Codificación Cómo se interpretan los bytes. Un encoding distinto produce caracteres rotos y rechazos al parsear B.
Fin de línea Cómo se parten las líneas (LF, CRLF, auto o secuencia propia). Si no coincide, captura y campos se desalinean.

Encoding y fin de línea

  • Use el encoding del archivo B real (p. ej. latin-1 en exports antiguos).
  • Windows suele enviar CRLF; Unix, LF. Auto sirve si el proveedor mezcla orígenes.
  • El Perfil A puede tener otro tipo; no tiene que coincidir con B.

Si cambia el tipo a mitad de diseño

Los campos del paso 4 dependen del tipo. Si ya hay estructura y cambia el formato, revise el paso 4 antes de publicar la definición Match.

Buenas prácticas

  • Elija el tipo que usa el archivo B de producción, no el más flexible.
  • Si A y B comparten layout, puede Copiar desde A en el hub B y luego confirmar tipo y campos.
  • Solo PA y ED pueden guardar. El resto ve el paso en solo lectura.
  • Completar los 6 pasos de B no habilita conciliar: faltan reglas y publicar (A + B + reglas).
