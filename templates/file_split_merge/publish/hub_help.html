Ayuda — Publicar versión

Congela el perfil de lectura, la operación (Split o Merge) y las reglas en una versión inmutable de este proyecto.

← Publicar

Alcance: este proyecto

Publicar afecta solo a {{ project.slug }}. La versión activa (current_version) es la que usará Ejecutar (SM1). Otros proyectos Split/Merge tienen su propio ciclo de versiones.

Qué se congela

  • Perfil de lectura — tipo de archivo, captura y campos (M2).
  • Operación — Split o Merge (M3).
  • Reglas — catálogo sm_rules del borrador (M3).

Tras publicar, esa versión queda inmutable. Se crea un nuevo borrador (copia editable) para seguir ajustando sin tocar lo ya publicado.

Checklist antes de publicar

IDRequisito
P1 Perfil completo: tipo, captura y al menos un campo (validación estricta).
P2 Reglas completas: operación elegida y mínimo ON (Split: partición max_rows / max_bytes / split_by_column; Merge: missing_columns).
P5 Toda regla habilitada con params válidos y campos del perfil existentes. Las deshabilitadas no bloquean.

Si algo falla, el hub muestra motivos pendientes o «Reglas inválidas (P5)» y el botón Publicar permanece deshabilitado. Corrija en Perfil o Reglas y vuelva aquí.

Flujo en el hub

  1. Revise el strip: borrador que se publicará (vN) y versión activa actual.
  2. Confirme el resumen (tipo, campos, operación, reglas ON) y el historial de versiones.
  3. Pulse Publicar vN y confirme el diálogo.
  4. Éxito → vN queda publicada y activa; aparece el nuevo borrador vN+1.

Después de publicar

  • Ejecutar (M5) — solo contra la versión publicada activa (SM1), no el borrador.
  • Historial (M6) — cada job guarda la versión que usó; jobs en curso no cambian de definición a mitad (P4).
  • Puede seguir editando el nuevo borrador y publicar de nuevo cuando esté listo.

Roles

RolPuede
PA / ED Publicar cuando el checklist esté OK.
GE / CO Ver el hub y el historial de versiones; no publican.

Qué no hace

  • No sube archivos ni genera ZIP / consolidado (eso es Ejecutar).
  • No es un “deploy” de producto: es congelar la definición ejecutable del proyecto.
  • No mezcla versiones de otros proyectos Split/Merge.
