Alcance: un proyecto

Esta pantalla ejecuta solo la definición publicada de {{ project.slug }}. Cada proyecto tiene su propio perfil, operación (Split o Merge) e historial de jobs. Pruebas con CSV, TXT o XLSX en proyectos distintos no se mezclan aquí.

Antes de ejecutar (SM1)

  • Debe existir una versión publicada activa (perfil + reglas congelados).
  • Sin versión activa, use Publicar; no se puede correr el borrador.
  • La operación (Split / Merge) y el criterio de partición o consolidación salen de esa versión.

Split vs Merge

OperaciónEntradaSalida
Split Exactamente 1 archivo N partes + manifest.json + ZIP
Merge Al menos 2 archivos 1 archivo consolidado

El tipo de archivo debe coincidir con el perfil publicado (mismo layout). Límite de seguridad Split: máximo 200 partes; si se supera, la corrida falla.

Vista previa vs ejecución

  • Vista previa — calcula métricas (y muestra efecto) sin guardar artifacts definitivos descargables.
  • Ejecutar — persiste el job, escribe salidas y habilita descargas mientras el TTL esté vigente.
  • Ambas corridas quedan en el historial de este proyecto.

Parseo y fallos

Se lee con el perfil publicado (parse soft: sin el rigor de content_type de Gate). Si el parseo falla o no hay filas útiles en Split, el job termina en fallido sin salida engañosa.

TTL y descargas

Los artifacts descargables caducan a los {{ ttl_days }} días desde la finalización. Los metadatos del job permanecen en historial tras el TTL.

Roles

RolPuede
PA / ED / GE Ejecutar, vista previa y descargar artifacts vigentes.
CO Ver pantallas / metadatos; no ejecuta ni descarga contenido.

Qué no hace

  • No publica versiones ni edita perfil/reglas (use Perfil, Reglas y Publicar).
  • No ejecuta el borrador: solo la versión publicada activa.
  • No muestra jobs de otros proyectos; el historial es por proyecto.
