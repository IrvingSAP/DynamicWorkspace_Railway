Cómo funciona Reverse Studio

Reverse Studio (Emisor de layouts) convierte una planilla amigable (CSV, Excel o delimitado) en el archivo rígido que exige el banco, el ERP o el proveedor (TXT posicional, JSON o XML), sin scripts sueltos.

Esta página describe el flujo completo. En cada pantalla también hay ayuda contextual (botón ? / Ayuda) con el detalle de esa vista.

Ruta rápida

  1. Crea un proyecto emisor y define la planilla de entrada.
  2. Define el layout de envío, mapea campos, publica la versión.
  3. Sube la planilla, genera el archivo y consulta el historial.
Roles PAAdmin — define, publica y gestiona miembros EDEditor — ajusta definición y genera GEGenerar — sube planilla y descarga el envío COConsulta — metadatos e historial; sin descarga de datos

Qué es Reverse Studio

Es el aplicativo de DynamicWorkspace pensado para equipos de tesorería, RRHH, operaciones e integradores que deben enviar archivos en un layout fijo, pero trabajan día a día con Excel o CSV.

En una frase

Un emisor de layouts: proyecto reutilizable con contrato de entrada, contrato de salida, mapeo versionado y generación auditable.

Resultado que entrega

  • Archivo de envío descargable (posicional / JSON / XML).
  • Informe de la corrida y errores.
  • Historial de quién generó qué, cuándo y con qué versión.
2

Cuál es la función de esta app

Función principal: parsear la planilla → aplicar mapeo y reglas → escribir el archivo que exige el receptor, siempre contra una definición publicada.

Problema que resuelve

  • El banco/ERP exige TXT, XML o JSON rígido.
  • El negocio solo maneja Excel/CSV.
  • Hoy se usan scripts frágiles o se edita el archivo a mano.

Qué ganas

  • Misma planilla cada ciclo (mes, quincena, lote).
  • Menos scripts y menos error humano.
  • Evidencia de emisión (versión + historial).
3

Qué no es (y qué sí usar en su lugar)

Reverse Studio no…

  • No es un validador “solo gate” (no deja de generar por sí mismo un certificado de calidad).
  • No es un ETL abierto a cualquier origen → destino.
  • No concilia dos archivos ni reemplaza un ERP.

Usa otra app si…

  • FILE GATE — solo necesitas validar que la planilla cumple un contrato.
  • FilePipe — necesitas orígenes/destinos fuera del MVP o un pipeline genérico.
4

Flujo de trabajo

Camino fijo del producto: planilla fácil → layout rígido.

  1. Entrada — define cómo viene la planilla (CSV / Excel / delimitado).
  2. Salida — define el layout de envío (posicional / JSON / XML).
  3. Mapeo + reglas — enlaza columnas de la planilla con campos del layout y limpia valores.
  4. Publicar — congela la definición; la generación solo usa la versión publicada.
  5. Generar — sube la planilla, ejecuta el job y descarga el archivo de envío.
  6. Historial — consulta corridas, filtros y descargas vigentes (TTL).
  7. FILE GATE (opcional) — exige una validación en verde de la misma planilla antes de generar.
5

Módulos del producto

Módulo Qué hace Tipos / notas
1 · Entrada Contrato de la planilla de negocio (campos, encoding, captura). CSV, Excel, delimitado
2 · Salida Contrato del layout que exige el receptor. TXT posicional, JSON, XML
3 · Mapeo Enlaces entrada → layout y reglas de transformación. direct, constant, concat, …
4 · Publicar Pasa el borrador a versión publicada e inicia un nuevo borrador. Sin publicar no hay emisión
5 · Generar Upload de planilla → job → descarga de layout + informe. PA / ED / GE
6 · Historial Listado filtrable de generaciones y evidencia. TTL de descargas; CO solo metadatos
7 · Bridge Pre-check opcional con FILE GATE (mismo hash de planilla). No genera el envío; solo bloquea o permite

Frente a FILE GATE y FilePipe

App Pregunta que responde Relación
Reverse Studio ¿Puedo generar el archivo de envío? Escribe el layout destino
FILE GATE ¿El archivo cumple el contrato? Complemento opcional (Módulo 7) antes de generar
FilePipe ¿Cómo transformo origen ↔ destino genéricos? Mismo motor técnico; Reverse lo empaqueta para emisión
7

Casos típicos

  • Pagos / banco — Excel de abonos → TXT posicional del banco.
  • Nómina — CSV de RRHH → XML del proveedor de pagos.
  • Altas ERP — planilla de altas → JSON batch.
  • Emisión mensual — misma definición publicada; nueva planilla cada ciclo.
  • Pre-check + emisión — validar en FILE GATE → generar en Reverse Studio.
