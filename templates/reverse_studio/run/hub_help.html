Ayuda — Generar archivo de envío

Suba la planilla, genere el layout con la definición publicada y descargue el resultado.

← Volver a generar

Qué es este módulo

Emite el archivo de envío (banco / ERP) a partir de una planilla de negocio. Usa solo la definición publicada (entrada + salida + mapeo + reglas). No edita el contrato ni publica versiones (GEN1 / GEN3).

Prerrequisitos

RequisitoDónde se resuelve
Definición publicadaMódulo 4 — Publicar. Sin ella el hub pide ir a publicar.
Planilla de producciónEsta pantalla (sección 1 · Subir).
Extensión correctaSegún el tipo de entrada publicado (csv / xlsx / delimitado) (GEN4).
PermisoPA / ED / GE generan; CO solo consulta (GEN2).

Flujo en esta pantalla

  1. Subir planilla — crea un job en estado listo (uploaded) contra la versión activa.
  2. Vista previa (opcional) — dry run de filas para validar sin cerrar el job completo.
  3. Generar archivo — job completo: parse → mapeo → reglas → serialización.
  4. Descargar — archivo de envío, informe y/o errores (TTL típico 7 días).

Acciones principales

AcciónEfecto
Subir planillaValida extensión/tamaño y deja el job listo en la tabla.
Vista previaPrueba el pipeline sin sustituir el resultado definitivo.
Generar archivoConfirma y produce salida + informe; estados completed / partial / failed.
DescargasEnlaces con TTL. Rol CO no descarga datos de negocio.
Generaciones recientesVista rápida; el listado filtrable es el Historial (Módulo 6).

Integración FILE GATE (opcional)

Si el bridge está activo (Módulo 7), antes de generar se exige una validación FILE GATE aceptada con el mismo content hash de la planilla (GEN10). Si aparece bloqueado, valide en FILE GATE o revise la evidencia / certificado desde los enlaces de la fila.

Roles

RolEn Generar
PA / ED / GESubir, vista previa, generar y descargar (según permisos del proyecto).
COVer estado de generaciones; sin subir ni descargar archivos con datos de negocio.

Qué no hace este módulo

  • No edita entrada, salida, mapeo ni reglas.
  • No publica la definición (eso es Módulo 4).
  • No sustituye al historial filtrable (Módulo 6).
  • El job no modifica la versión publicada.
