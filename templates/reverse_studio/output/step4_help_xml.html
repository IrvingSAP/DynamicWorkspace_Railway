Ayuda — Campos del layout (XML)

Cada campo se escribe como elemento hijo (path) dentro del registro. Raíz y tag de registro van en el paso 3.

← Volver al paso 4 Ir al paso 5

Qué es

El tipo del paso 1 es XML. El envoltorio (root_element, record_element, namespace, declaración) se define en el paso 3. Aquí solo los hijos de cada registro.

Flujo recomendado

  1. Fije en el paso 3 los nombres de raíz y de registro que exige el proveedor.
  2. Opcional: Cargar desde entrada; luego ponga el elemento hijo real (Documento, Monto…).
  3. El path es el tag (o ruta de hijos) dentro de cada registro, no el XPath del documento entero.

Campos de esta pantalla

ControlSignificado
Nombre Clave para el mapeo. Puede ser distinto del tag XML.
Elemento hijo (path) Tag bajo el registro. Obligatorio. Ejemplo: con registro pago, path documento → <pago><documento>….
Etiqueta / Order / Tipo / Oblig. Metadatos. El XML usa el path, no la etiqueta.

Relación con el paso 3

Namespace y declaración XML no se repiten por campo. Si el esquema usa prefijos, alinéelos con el namespace del paso 3; no invente un segundo xmlns aquí.

Si algo no encaja

SituaciónQué hacer

Path vacíoEl editor lo exige. No use start/end de TXT posicional.
Cargar desde entrada deja path = nombreEsperado: cámbielo al tag del XSD del receptor.
