Propósito de la página

El hub resume el estado del proyecto {{ project.name }} y da acceso a cada etapa: acceso (miembros), definición (origen → destino → mapeo → reglas → publicar) y ejecución (archivo + transformar, historial, integración FILE GATE). La publicación de la versión completa se hace aquí (no en los hubs de origen o destino).

Quién: cualquier miembro ve el hub; PA gestiona miembros; editores publican y ejecutan. Ejemplo: con origen, destino, mapeo y reglas listos, pulse Publicar vN y luego use Fase C para transformar un archivo de producción.

Ciclo de vida (stepper)

Cada paso muestra número o ✓ cuando está hecho. Puede pulsar un paso para ir a esa pantalla (Publicar dispara la misma acción que el botón de cabecera si la definición está completa).

FasePasosPara qué sirve
A — Acceso Crear proyecto · Visibilidad · Miembros Quién ve y quién edita. Crear y visibilidad quedan en ✓ al existir el proyecto. Miembros pasa a ✓ cuando hay más de un integrante (si usted es PA).
B — Definición 1 Origen · 2 Destino · 3 Mapeo · 4 Reglas · 5 Publicar Cómo se lee, mapea, transforma y escribe el archivo. Publicar exige los cuatro anteriores completos. El ✓ de Publicar aparece cuando ya hay versión publicada.
C — Ejecución 6 Archivo + transformar · 7 Historial · 8 FILE GATE Subir archivo de producción, ejecutar el job y revisar descargas. Los pasos 6 y 7 pasan a ✓ cuando hay al menos una corrida completada o parcial. El paso 8 abre la integración opcional con FILE GATE (ver más abajo). Si el pre-check no está activado, el círculo permanece en 8 (pendiente); el enlace igual funciona.

Paso 8 · FILE GATE

Es un atajo a Integración FILE GATE de este proyecto FilePipe. No transforma el archivo: decide si FilePipe puede o no ejecutar la transformación. FILE GATE es otro tipo de proyecto (contrato, políticas, validar archivo). FilePipe es la transformación. El paso 8 solo une ambos cuando usted enciende el bridge.

TemaQué implica
¿Está activa por defecto? No. Hasta que marque «Exigir validación FILE GATE» y elija un proyecto GATE de la misma compañía, FilePipe transforma sin pre-check. El stepper se ve gris (is-pending) si el flag está apagado.
Qué hace al activarla 1) Sube el archivo en FilePipe. 2) Ese mismo contenido debe haberse validado y aceptado en el proyecto FILE GATE vinculado (mismo content hash, no el nombre del fichero). 3) Solo entonces arranca Ejecutar transformación. 4) Si no hay corrida aceptada, el estado es error/parcial, o caducó la frescura (p. ej. 7 días), FilePipe bloquea el job.
Estados que abren el paso Solo corridas GATE en passed o, si lo configura, también passed_with_warnings. failed, partial y error nunca abren la transformación.
Bypass En el MVP no hay excepción: ni PA puede saltarse el pre-check mientras el flag esté activo. Desactivar el flag restaura el comportamiento habitual de FilePipe (el vínculo al proyecto GATE puede quedar guardado).
Quién configura Roles PA y ED. El resto puede ver el estado (activo/inactivo) pero no cambiarlo.

Ejemplo: exige GATE, vincula pq-fg-entrada-01, sube entrada.txt en ambos lados. Si FILE GATE aceptó ese contenido, FilePipe transforma; si no, verá un bloqueo pidiendo validar primero en FILE GATE.

Pestañas y tarjetas

SecciónQué hace
Resumen Métricas: tipo de origen/destino y pasos n/6, cantidad de mapeos, etiqueta de versión. Debajo, tarjetas de atajo: Definir origen, Definir destino, Mapeo, Reglas y Publicar versión (misma acción que el botón de cabecera).
Origen Asistente de 6 pasos del archivo de entrada (tipo, inicio, fin, campos, reglas, informe). Puede importar estructura desde un perfil publicado de GATE, CLEAN, otro FilePipe, FILE MATCH, Reverse Studio o FILE SPLIT/MERGE, o desde un borrador STRUCTURE SCOUT.
Destino Asistente de 6 pasos del archivo de salida (tipo, encoding, layout, campos, serialización, validación). En TXT de ancho fijo, longitudes (p. ej. correlativo) deben caber los valores generados.
Mapeo Correspondencia origen → destino: directo, constante, concat, generado, split, expresión. Un mapeo ya guardado se edita con Editar, no con Añadir mapeo.
Reglas Pipeline post-mapeo (trim, mayúsculas, fechas, pad, default…). Completar reglas habilita Publicar.
Archivo Carga de muestra (definición) o producción (ejecución).
Ejecutar Solo preview (no deja historial de corrida) o Ejecutar transformación (genera salida, informe y fila en historial). Requiere versión publicada. Si el bridge FILE GATE está activo, además exige una corrida GATE aceptada con el mismo hash.
Miembros Invitar, cambiar rol o revocar (solo PA). Pestaña visible si puede gestionar miembros.
