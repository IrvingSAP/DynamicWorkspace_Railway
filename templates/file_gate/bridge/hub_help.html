FILE GATE · Módulo 6 · ayuda

Cómo funciona el bridge FilePipe

El bridge es un pre-check: FilePipe no transforma hasta que exista una corrida FILE GATE aceptada del mismo archivo (mismo content hash). FILE GATE no genera destino de negocio.

← Volver al bridge

Qué es esta pantalla

  • Muestra los proyectos FilePipe / DMS de la misma compañía que apuntan a este gate.
  • Desde aquí solo se consulta el vínculo. El flag «Exigir FILE GATE» se activa en el lado DMS.
  • Si no hay vínculos, verá el estado vacío hasta que un PA/ED de FilePipe configure la integración.

Flujo resumido

  1. En FilePipe se activa «Exigir validación FILE GATE» y se elige este proyecto.
  2. El operador valida el archivo aquí (Módulo 3) y obtiene un resultado aceptado.
  3. Al subir el mismo archivo en FilePipe, el sistema busca una corrida con el mismo hash.
  4. Si el gate está en verde (y fresco), FilePipe puede transformar; si no, queda bloqueado con enlaces a validar.

Matching por content hash

ReglaDetalle
Clave de emparejecontent_hash (SHA-256) del archivo de entrada.
Qué no cuentaEl nombre del archivo ni la ruta. Dos archivos con el mismo contenido comparten hash.
Origen del hashSe calcula al validar en FILE GATE y al subir en FilePipe (intake DMS).
Si no hay job con ese hashFilePipe bloquea: hay que validar primero en este proyecto.

Qué estados acepta FilePipe

Política «Acepta»Permite transformar
solo passedÚnicamente gate limpio, sin errores.
passed + warningsTambién passed_with_warnings (dentro del umbral).
Nuncafailed, partial o error técnico. No abren el paso.

Frescura: la corrida debe estar dentro de la ventana configurada (p. ej. 7 días). Un passed antiguo fuera de ventana también bloquea.

Quién configura y permisos

  • Solo PA / ED del proyecto DMS activan o cambian el flag y el proyecto gate.
  • Desde FILE GATE, los miembros del proyecto (y consulta CO según permisos) ven el vínculo.
  • En el MVP nadie puede saltar el pre-check si está activo (ni el PA de FilePipe).
  • Ambos proyectos deben pertenecer a la misma compañía.

Prerrequisitos habituales

  • Contrato FILE GATE publicado (esquema + políticas).
  • Al menos una validación finalizada con el hash del archivo que se transformará.
  • Estado del gate dentro de la política de aceptación y de la ventana de frescura.

Si FilePipe bloquea, valide aquí el mismo archivo, espere un resultado aceptado y reintente Ejecutar en DMS.
