Qué es este listado

Es la puerta de entrada a FILE GATE (Validador). Cada fila es un proyecto con un contrato de validación versionable: define cómo debe leerse el archivo y qué se acepta o rechaza. No transforma ni genera un archivo de salida. Está aislado de FilePipe, FILE MATCH y Reverse Studio.

  • Solo se listan proyectos de su compañía (alcance UF).
  • Aparecen los proyectos donde usted es miembro y los públicos de la compañía (aunque no sea miembro).
  • Desde aquí crea un proyecto nuevo o abre el hub de uno existente.

El filtro de Visibilidad en la barra de la tabla permite restringir a públicos o privados. La tabla admite búsqueda y paginación.

Visibilidad y acceso

  • Privado: solo la membresía activa puede ver y trabajar según el rol.
  • Público: UF de la misma compañía pueden ver el proyecto sin ser miembros (consulta). Editar, publicar o validar siguen exigiendo el rol adecuado.
  • El creador queda siempre como PA, independientemente de la visibilidad.

Roles (resumen)

RolPermisos principales
PAAdmin: miembros, editar esquema y políticas, publicar, validar, bridge.
EDEditar esquema y políticas; publicar; validar.
GEValidar y descargar informe (sin editar el contrato).
COConsulta: ver hub e historial; sin descargas de filas de negocio.

Los miembros se gestionan dentro de cada proyecto (hub → Miembros, solo PA).

Cómo empezar

  1. Pulse + Nuevo proyecto (nombre, código/slug y visibilidad).
  2. En el hub, complete el esquema (6 pasos) y las políticas.
  3. Opcional: Importar estructura desde otra app (GATE, CLEAN, FilePipe, Match, Reverse, Scout) al borrador del esquema; no clona políticas.
  4. Publique el contrato (esquema + política). Validar usa solo la versión publicada.
  5. Valide un archivo; revise informe e historial. El bridge FILE GATE es un extra opcional para otras apps.

Regla de producto: no se valida contra un borrador. Guía completa: menú FILE GATE → Ayuda.

Qué no es este listado

  • No muestra proyectos de FilePipe, FILE MATCH ni Reverse Studio.
  • No edita el esquema ni las políticas (eso ocurre en el hub de cada proyecto).
  • No ejecuta validaciones ni sube archivos de producción.
  • No transforma ni emite layouts: solo valida.
