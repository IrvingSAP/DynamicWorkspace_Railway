Cómo funciona FILE GATE

FILE GATE (Validador de archivos) permite definir un contrato (esquema) y comprobar si un archivo real lo cumple — sin transformar ni generar salida de negocio.

Esta página describe el flujo completo. En cada pantalla también hay ayuda contextual (botón ? / Ayuda) con el detalle de esa vista.

Ruta rápida

  1. Crea un proyecto validador y define el esquema (contrato).
  2. Ajusta políticas, publica la versión y sube un archivo.
  3. Revisa el informe, el certificado y el historial.
Roles PAAdmin — define esquema, publica y gestiona miembros EDEditor — ajusta contrato/políticas y valida GEGenerar — ejecuta validación y descarga informe COConsulta — ve historial/metadatos; sin descarga de filas

Qué es FILE GATE

Es el aplicativo de DynamicWorkspace pensado para equipos de operaciones, control de calidad de datos, integradores y supervisores de intercambio que necesitan certificar que un archivo cumple el layout acordado antes de cargarlo al ERP, enviarlo al banco o pasarlo a una transformación.

En una frase

Un validador de archivos: proyecto reutilizable con esquema versionado, políticas de decisión, ejecución y evidencia auditable.

Resultado que entrega

  • Veredicto: OK / con advertencias / rechazado / parcial.
  • Informe de errores (resumen + detalle por fila/campo).
  • Certificado ligero (hash + versión + resultado) e historial.
2

Cuál es la función de esta app

Función principal: parsear el archivo → validar campos y reglas de contenido → aplicar políticas → emitir un informe de conformidad contra la versión publicada del contrato.

Problema que resuelve

  • Archivos corruptos o fuera de layout llegan tarde al proceso.
  • Validar “a ojo” en Excel no escala ni audita.
  • Scripts puntuales no tienen roles, versiones ni historial.

Qué ganas

  • Detección temprana antes de la carga o el envío.
  • Contrato reutilizable (misma definición cada ciclo).
  • Evidencia para proveedores, terceros y auditoría interna.
3

Qué no es (y qué sí usar en su lugar)

FILE GATE no…

  • No escribe un archivo de salida de negocio (no transforma).
  • No mapea origen → destino ni serializa un layout nuevo.
  • No concilia dos archivos ni corrige automáticamente el archivo completo.

Usa otra app si…

  • FilePipe — necesitas transformar y generar un archivo destino.
  • Reverse Studio — tienes Excel/CSV y debes emitir el layout del banco/ERP.

Sí puede exportar un archivo de errores (CSV/JSON de rechazos): eso es informe, no transformación.

4

Flujo de trabajo

Camino del producto: definir contrato → validar archivo → evidencia.

  1. Esquema — define tipo, encoding, captura, campos y reglas de contenido (asistente de 6 pasos).
  2. Políticas — cómo recolectar errores, tope de errores y umbral de rechazo.
  3. Publicar — congela el borrador; las validaciones usan solo la versión publicada.
  4. Validar — sube el archivo, ejecuta el job y obtén el veredicto.
  5. Informe — resumen, detalle, descargas y certificado ligero.
  6. Historial — consulta corridas, filtros y TTL de evidencias.
  7. Bridge FilePipe / Reverse — opcional: exigir FILE GATE en verde antes de transformar o generar.
5

Módulos del producto

Módulo Qué hace Notas
1 · Esquema Contrato de validación (tipo, captura, campos, reglas). Reusa SourceProfile; no define destino
2 · Políticas Recolección, corte (max_errors) y umbral de decisión. abort / collect_all / reject_threshold
3 · Validar Upload + parseo + validación + persistencia del job. Solo contra versión publicada
4 · Informe Resumen, detalle de errores, descargas y certificado. Hash + versión + resultado
5 · Historial Listado filtrable de validaciones y auditoría. TTL de evidencia; CO solo metadatos
6 · Bridge Vínculo con FilePipe (y emisores Reverse) para pre-check. Matching por content_hash
Abrir validador Nuevo proyecto
6

Estados de una validación

Estado Significado
passed 0 errores (advertencias permitidas según política).
passed_with_warnings 0 errores, hay advertencias.
failed Hay errores o se superó el umbral / abort.
partial Tope de filas o max_errors antes de llegar al final del archivo.

Severidades

  • Error — obligatorio vacío, tipo inválido, longitud/patrón fallido.
  • Advertencia — encoding distinto, columnas extra, filas cortas.
  • Info — filas omitidas por captura, detección automática.

Reglas clave

  • Solo se valida contra versión publicada.
  • El job no modifica el perfil ni el archivo de entrada.
  • Aislamiento por compañía + membresía del proyecto.

Frente a FilePipe y Reverse Studio

App Pregunta que responde Relación
FILE GATE ¿El archivo cumple el contrato? Solo valida; no escribe salida de negocio
FilePipe ¿Cómo transformo origen → destino? Puede exigir FILE GATE en verde (bridge) antes de ejecutar
Reverse Studio ¿Puedo generar el archivo de envío? Puede exigir validación de la planilla antes de emitir

Casos típicos

  • Intercambio bancario — validar layout de abonos antes de enviar al banco.
  • Nómina / RRHH — comprobar TXT posicional del ERP antes de la carga de pagos.
  • Proveedores — gate de recepción: el proveedor sube y ve el informe de conformidad.
  • Reportes regulatorios — certificar columnas y tipos exigidos en un CSV.
  • Pre-check FilePipe / Reverse — exigir validación en verde antes de transformar o generar.
  • Onboarding de layouts — documentar el contrato y usarlo como prueba de aceptación.
