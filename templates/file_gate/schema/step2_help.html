Ayuda — Inicio de captura

Define desde qué punto del archivo empiezan las filas que el gate va a validar. Todo lo anterior se omite y no cuenta en el informe.

← Volver al paso 2

Para qué sirve

Un archivo de proveedor casi nunca es “solo datos”. Suele traer título, membrete, fecha de generación o líneas de control antes del detalle. Si el inicio está mal, FILE GATE trata esa basura como registros: fallan campos obligatorios, tipos y patrones, y el porcentaje de rechazo se dispara aunque el detalle sea correcto.

Este paso guarda capture_start en el borrador del contrato. Las corridas de Validar usan la versión publicada. La unidad es siempre líneas (1 = primera línea del archivo).

Qué entra y qué se ignora

Zona del archivoEfecto en la validación
Antes del inicio Se omite. No genera errores de campo ni cuenta como fila validada.
Desde el inicio hasta el fin (paso 3) Cada línea (o registro) se evalúa contra los campos y las reglas del contrato.
Después del fin Lo define el paso 3 (pies, totales, firmas). Aquí solo fija el arranque.

Modos de inicio

Elija el modo que describe el archivo real del proveedor, no “el más flexible”. Los parámetros aparecen en el paso según el modo.

ModoCuándo usarloCómo arranca la captura
Primera línea
first		 El archivo es puro detalle: no hay título ni cabecera que saltar. Línea 1 inclusive.
Línea específica
line_number		 La cabecera tiene siempre el mismo número de líneas (membrete fijo). La línea indicada (1-based) inclusive. Ejemplo: línea 10 si las 9 primeras son corporativas.
Tras N líneas iniciales
after_header_block		 Quiere expresar “saltar N líneas”, no “empezar en la línea N”. Tras saltar N líneas: con skip_lines = 3 la primera fila validada es la 4.
Marcador de inicio
marker_start		 Hay un texto fijo que anuncia el detalle (=== DATOS ===). La línea siguiente a la primera que contiene el texto. El marcador no se valida.
Tras patrón regex
after_pattern		 El anuncio de datos varía un poco, pero encaja en una expresión (p. ej. ^REGISTRO\|). La línea siguiente a la primera coincidencia. El patrón no se valida como fila.
Tras líneas en blanco
after_blank_run		 El detalle empieza después de un bloque vacío que separa el encabezado. Tras N líneas consecutivas sin texto (solo espacios cuenta como vacía). Arranca en la inmediata siguiente.

Cómo elegir

  1. Si no hay nada que saltar → Primera línea.
  2. Si el membrete mide siempre lo mismo → Línea específica o Tras N líneas (no mezcle ambos criterios).
  3. Si hay un rótulo o una línea de control reconocible → Marcador (texto literal) o Patrón (regex).
  4. Si el corte es un hueco en blanco → Tras líneas en blanco.

Coherencia con el paso 3

El fin de captura debe quedar después de este inicio, en la misma unidad (líneas). Si ambos usan número de línea, un fin menor o igual que el inicio no publica. Con fin en EOF se lee desde este arranque hasta la última línea.

Si el archivo no encaja

SituaciónQué hace FILE GATE
La línea de inicio queda más allá del archivo No hay filas de captura. El informe avisa CAPTURE_OUT_OF_RANGE.
No aparece el marcador ni el patrón No avanza el inicio: se lee desde el principio. Revise el texto o publique de nuevo tras corregir.
No hay suficientes líneas en blanco Tampoco avanza el inicio. El detalle se mezclará con el encabezado.

Buenas prácticas

  • Mida el archivo real del proveedor (una muestra), no un ejemplo “limpio” de laboratorio.
  • No use regex si un número de línea o un marcador literal bastan: es más estable ante cambios menores.
  • El marcador y el patrón no entran como fila validada; el detalle empieza en la línea siguiente.
  • Guarde el borrador. Solo PA y ED pueden editar; el resto ve el paso en solo lectura.
  • Tras publicar, Validar usa la versión congelada: un cambio de inicio en el borrador no afecta corridas hasta la próxima publicación.
