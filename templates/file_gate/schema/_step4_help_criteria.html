{# Criterios comunes de rechazo — ayudas paso 4 FILE GATE #}

Criterios de rechazo (todos los tipos)

En FILE GATE cada campo es un criterio de conformidad, no un origen para mapear a un destino. Al publicar se exige al menos un campo. Las incidencias usan el nombre interno.

PropiedadSignificado en el gate
Nombre interno Identificador único (minúsculas, números y guión bajo). Aparece en el informe y en cada incidencia.
Tipo de contenido Forma esperada (numérico, fecha, alfanumérico, custom…). Un valor incompatible genera error de contenido.
Campo obligatorio Si está vacío, cuenta como rechazo. El umbral de Políticas decide si el job falla.
Patrón / formato fecha Si el tipo es custom, regex propia. Si es fecha, indique date_format (p. ej. DD/MM/YYYY).

Opcional: Importar estructura clona campos al borrador desde otra app. No publica ni copia políticas. Solo PA y ED editan. Guarde el borrador; Siguiente va al paso 5.
