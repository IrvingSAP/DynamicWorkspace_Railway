Ayuda — Tipo de archivo del contrato

Fija cómo FILE GATE abre cada archivo a validar: formato, bytes y cortes de línea. Sin este paso no se publica el contrato.

← Volver al paso 1

Para qué sirve

El tipo declara qué archivo espera el proveedor, no “el más cómodo de modelar”. Condiciona las extensiones al Validar, el parser y la pantalla de campos (paso 4). Encoding y fin de línea deciden cómo se leen los bytes antes de aplicar captura, campos o reglas.

Se guarda en el borrador. Las corridas usan solo la versión publicada.

Qué decide este paso

ElementoEfecto en la validación
Tipo de archivo Formato y parser. Las extensiones permitidas al subir salen de este tipo.
Codificación Cómo se interpretan los bytes. Un encoding distinto al del archivo produce caracteres rotos y rechazos de contenido.
Fin de línea Cómo se parten las líneas (LF, CRLF, auto o secuencia propia). Si no coincide, la captura y los campos se desalinean.

Encoding y fin de línea

  • Use el encoding del archivo real (p. ej. latin-1 en exports antiguos, no UTF-8 “por si acaso”).
  • Detección automática ayuda al subir una muestra; el contrato publicado debe quedar con un valor estable.
  • Windows suele enviar CRLF; Unix, LF. Auto sirve si el proveedor mezcla orígenes.
  • La secuencia personalizada solo si el catálogo lo permite y el archivo no usa un fin de línea estándar.

Si cambia el tipo a mitad de diseño

Los campos del paso 4 dependen del tipo. Si ya hay estructura y cambia a otro formato, esa definición puede quedar inválida. Confirme o redefina el paso 4 antes de publicar.

Buenas prácticas

  • Elija el tipo que usa el proveedor, no el más flexible.
  • Sin tipo de archivo el contrato no se publica.
  • Solo PA y ED pueden guardar. El resto ve el paso en solo lectura.
  • Tras publicar, Validar usa el snapshot congelado hasta la próxima publicación.
