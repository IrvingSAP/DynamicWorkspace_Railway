Ayuda — Campos de ancho fijo

Cada campo se corta por posiciones de carácter en la línea. Tipo actual: {{ file_type_code|default:"txt_fixed" }}.

← Volver al paso 4

Para qué sirve esta pantalla

El archivo es una línea continua (TXT posicional). FILE GATE extrae cada valor por columnas de carácter (1 = primer carácter) y lo valida contra tipo, obligatoriedad y patrón. La regla visual de la pantalla sirve para alinear rangos; no es el archivo del proveedor.

Editor de cada campo

Campo en pantallaEfecto en la validación
Nombre (slug) Identificador interno único. Sale en el informe de incidencias.
Etiqueta Texto legible en pantallas. No sustituye al nombre interno.
Cómo definir la posición
  • Inicio y fin — primera y última columna inclusive (1-based).
  • Inicio y longitud — desde la columna inicial, N caracteres (end = start + length − 1).
  • Desde carácter — el valor empieza a partir de un marcador en la línea.
Inicio (1-based) Primera columna del campo. El primer carácter de la línea es 1, no 0.
Fin (inclusive) Última columna incluida. Debe ser ≥ inicio. Los rangos numéricos no deben solaparse.
Longitud Cantidad de caracteres desde el inicio (modo longitud).
Marcador char En modo «desde carácter»: el campo inicia al encontrar ese texto en la línea.
Tipo contenido Forma esperada del recorte. Incompatible → error de contenido.
Campo obligatorio Recorte vacío → rechazo de campo.
Patrón regex / formato fecha Visible si el tipo es custom o fecha/datetime.

Ejemplo

Línea de muestra del editor:

12345JUAN      2500001
  • documento → inicio 1, fin 5 (o longitud 5).
  • nombre → inicio 6, longitud 10 (columnas 6–15, con padding).

Si el recorte se desliza un carácter, fallan tipos y longitudes en todo el archivo.
