Ayuda — Reglas de limpieza

Catálogo ordenado y explícito. Nada se limpia si no hay regla. El orden forma parte del contrato.

← Volver a reglas Hub

Para qué sirve

Define qué se reescribe sobre el perfil de lectura: trim, mayúsculas, mapas de códigos, find/replace, plantillas, etc. Se edita en borrador; al publicar se congela junto con el perfil. Ejecutar usa solo esa versión publicada.

Reutiliza operadores de FilePipe, pero solo el subset de normalización. No mapea a un esquema de destino ni valida un contrato FILE GATE.

Prerrequisito

Hace falta al menos un campo en el perfil para reglas por campo. Si falta, verá el aviso y un atajo a Perfil. El stepper marca Reglas cuando hay al menos una regla habilitada.

replace_map vs replace vs compose

  • replace_map — match exacto del valor entero (p. ej. M → Masculino). Mas no coincide con M. Case-sensitive salvo que active lo contrario. Prefiera null_tokens para vacíos, no un mapa con clave vacía.
  • replace — fragmento dentro del texto (p. ej. quitar guiones de un RUT). find no puede ir vacío. Sin regex en MVP.
  • compose — reescribe con plantilla. {seq} es un contador por job (se reinicia en cada ejecución). El valor de {field:X} es el de X después de las reglas anteriores de esa fila. No es concat de FilePipe hacia otro esquema.

Roles

  • PA / ED añaden, editan, reordenan, activan y eliminan.
  • GE / CG / CO consultan el pipeline; no lo modifican.

Qué no hace este módulo

  • No publica la versión (eso es Publicar; allí se revalidan las reglas habilitadas).
  • No sube ni limpia un archivo de producción (eso es Ejecutar; allí ve el preview del efecto).
  • No valida umbrales GATE ni mapea a destino FilePipe.
  • No aplica limpiezas “mágicas”: si no hay regla ON, el valor no cambia.

Orden sugerido

  1. Perfil con nombres de campo estables.
  2. Añada reglas y deje el orden como debe correr el job.
  3. Publicar → Ejecutar (preview y job) → Historial.
