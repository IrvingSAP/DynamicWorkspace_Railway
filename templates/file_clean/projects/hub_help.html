Qué es este hub

Es el punto de entrada del proyecto File Clean. Agrupa el perfil de lectura, las reglas de limpieza, la versión publicada, las ejecuciones (jobs) y el historial. No es File Gate (no valida contrato de producción) ni FilePipe (no transforma a un destino de negocio).

  • Objetivo: normalizar un archivo con reglas explícitas y entregar archivo limpio + log auditable.
  • Strip superior: borrador, versión activa publicada, último job y conteo de miembros.
  • Stepper + paneles: avance del ciclo y accesos a cada módulo.
  • Miembros: botón visible solo para el administrador (PA).

Stepper — qué hace cada paso

#PasoPara qué sirveCuándo se marca
1 Perfil Cómo se lee el archivo (tipo, encoding, captura, campos). Wizard de 4 pasos. ✓ cuando el borrador tiene los 4 pasos listos.
2 Reglas Catálogo ordenado: trim, replace_map, replace, compose, dedupe… Solo reglas explícitas. ✓ con al menos una regla habilitada; requiere perfil con campos.
3 Publicar Congela perfil + reglas en una versión activa. Sin publish parcial. ✓ si ya hay versión publicada.
4 Ejecutar Suba el archivo, preview o job completo; salida limpia + change log. ✓ tras al menos un job completado. Requiere versión publicada.
5 Historial Auditoría de jobs, hashes, métricas y descargas (TTL 7 días). Consulta continua: no se marca como «hecho»; queda activo al publicar.

Colores de los botones

  • Verde sólido (primary): siguiente paso pendiente — acción recomendada.
  • Verde suave (info): paso ya completado — puede seguir editando o revisando.
  • Gris (secondary): aún no habilitado o acción secundaria.

Orden de trabajo recomendado

  1. Revise Miembros (PA) si otras personas deben editar o ejecutar.
  2. Complete el Perfil de lectura (4 pasos).
  3. Defina y habilite Reglas.
  4. Publique la versión (perfil + reglas).
  5. Ejecute con un archivo de prueba → revise resultado y descargas.
  6. Use el Historial para auditar jobs y TTL.

Regla de producto (FC1): solo se ejecuta la versión publicada activa, no el borrador.

Borrador vs versión publicada

  • Perfil y reglas se editan en borrador hasta publicar.
  • Al publicar se congela una versión activa y se crea un nuevo borrador (copia) editable.
  • Si cambia el borrador después de publicar, debe volver a publicar para que Ejecutar use esos cambios.
  • Los jobs antiguos no se invalidan solos; siguen asociados a la versión con la que se ejecutaron.

Roles (resumen)

RolEn este hub

Detalle de invitaciones: pantalla Miembros → Ayuda. Guía de producto: menú File Clean → Ayuda.

Qué no hace este hub

  • No edita campos del perfil ni reglas (eso está en cada módulo del stepper).
  • No sube archivos de limpieza (eso es Ejecutar).
  • No publica automáticamente: hay que entrar a Publicar y confirmar.
  • No valida contrato (File Gate) ni genera destino ETL (FilePipe).
  • En Ejecutar, File Clean lee y limpia; no rechaza filas por content_type (eso es Gate).
