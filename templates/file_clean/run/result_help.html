Ayuda — Resultado de limpieza

Cómo leer el estado, las métricas, la vista previa y las descargas de esta corrida.

← Volver al resultado Nueva corrida

Para qué sirve

Resume esta ejecución contra la versión publicada indicada en el encabezado (p. ej. v3), no el borrador actual. Si es vista previa, verá la marca preview: no hay artifacts definitivos.

El detalle de auditoría (snapshot de reglas, TTL, borrar corrida) está en Historial → Detalle. Esta pantalla es el resultado inmediato tras Ejecutar.

Estado (banner)

EstadoSignificado
Completado La limpieza terminó. Hay métricas; si no es preview, hay archivo de salida.
Completado · vista previa La muestra se procesó. No se generó archivo limpio ni logs descargables.
Fallido Falló el parseo, la serialización o una regla. El mensaje del banner explica el motivo. No hay output engañoso: no descargue un “limpio” si el job falló.

El hash de entrada (y de salida si hay) identifica el contenido. Duración en milisegundos si está disponible.

Métricas

IndicadorQué mide
Filas leídas Registros parseados tras captura (inicio/fin) y layout publicado.
Filas escritas Filas en el archivo limpio. Puede ser menor si hubo dedupe_rows.
Celdas cambiadas Valores que alguna regla reescribió. Cero no es error: el archivo ya coincidía con las reglas.
Dedupe Filas eliminadas por la regla global de duplicados, si estaba ON en esa versión.

Avisos de lectura

Si hay incidencias de layout o captura (línea, campo, código, mensaje), aparecen aquí. File Clean no rechaza filas por content_type; eso es FILE GATE. Un delimitador o captura mal publicados suelen dejar cero filas leídas.

Cambios por regla

Conteo de celdas tocadas por cada code (trim, replace, compose…). Sirve para ver qué regla impactó más en esta corrida.

Vista previa (tablas Antes / Después)

Primeras filas según las reglas publicadas. En preview, {seq} arranca en seq_start de la regla compose. No sustituye descargar el archivo entero.

Descargas

ArchivoContenido
Archivo limpio Mismo tipo que el perfil, con reglas aplicadas. Caduca a los {{ ttl_days }} días.
Log JSON / CSV Bitácora: fila, campo, código de regla, valor antes y después.
  • Solo en jobs completados que no son vista previa, y si su rol puede descargar (PA / ED / GE).
  • CO no descarga contenido. Tras el TTL, use Historial: los metadatos siguen; los archivos no.

Qué no hace este resultado

  • No vuelve a limpiar ni cambia el borrador de perfil o reglas.
  • No es el informe de FILE GATE (no hay umbral passed/failed).
  • No lista todas las corridas (eso es Historial).
