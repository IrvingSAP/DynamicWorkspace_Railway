Ayuda — Detalle de limpieza

Lectura de una corrida ya finalizada: metadatos, métricas, snapshot de reglas y descargas.

← Volver al detalle Historial

Para qué sirve

Esta pantalla documenta una ejecución concreta (job), no el borrador actual del perfil ni de las reglas. Lo que ve aquí quedó congelado al correr Ejecutar con la versión publicada de ese momento.

Los metadatos (quién, cuándo, hashes, métricas) permanecen. Los archivos de salida y logs caducan a los {{ ttl_days }} días desde que el job finalizó. Una vista previa (dry_run) no genera artifacts definitivos.

Qué ve en esta pantalla

BloqueSignificado
Franja del job Identificador corto, versión publicada usada, marca de vista previa y estado del TTL (vigente o expirado).
Metadatos Estado, nombre de archivo, versión, ejecutor, fecha de fin, hashes de entrada/salida y plazo de artifacts.
Filas leídas / escritas Cuántas filas parseó el perfil publicado y cuántas escribió el archivo limpio. Difieren si hubo dedupe_rows u omisiones.
Celdas cambiadas Cuántos valores reescribió alguna regla. Cero no es error: el archivo pudo coincidir ya con las reglas.
Dedupe Filas eliminadas por la regla global de duplicados, si estaba habilitada en esa versión.
Cambios por regla Conteo de celdas tocadas por cada code (trim, replace, etc.). Sirve para auditar qué regla impactó más.
Reglas aplicadas (snapshot) Pipeline habilitado en esa corrida (orden, código, campo). No es el borrador de hoy; si luego cambió reglas y no volvió a publicar/ejecutar, aquí sigue el antiguo.
Descargas Archivo limpio, log JSON y log CSV, si el TTL sigue vigente y su rol lo permite.
Resultado Atajo a la pantalla de resultado de Ejecutar de este mismo job (resumen de la corrida).

Hashes

El hash de entrada identifica el archivo subido; el de salida, el archivo limpio. Sirven para demostrar integridad y para buscar la misma corrida desde el listado del historial. Si el job falló o es solo vista previa, el hash de salida puede ir vacío.

Descargas y TTL

  • Plazo: {{ ttl_days }} días desde la finalización. Después el aviso «TTL expirado»: metadatos sí, archivos no.
  • Archivo limpio — resultado de la limpieza (no el original).
  • Log JSON / CSV — bitácora de cambios por celda/regla, para auditoría o conciliación.
  • Vista previa — no hay descargas de salida definitiva; use Ejecutar en modo real para generarlas.
  • Si el TTL está vigente y no ve botones, su rol es consultor (CO) o el job no dejó artifacts.

Roles

RolEn el detalle
PA / ED / GEVen metadatos, métricas, snapshot y pueden descargar artifacts vigentes.
COVen metadatos y métricas. No descargan contenido (archivo limpio ni logs).

Eliminar esta corrida solo aparece si usted la ejecutó. Pide confirmación y borra registro y artifacts. No borra corridas de otros.

Qué no hace este detalle

  • No vuelve a limpiar el archivo ni cambia el borrador de perfil o reglas.
  • No publica una versión nueva (eso es Publicar).
  • No es el listado filtrable (eso es Historial).
  • No valida un contrato FILE GATE ni mapea a FilePipe.
