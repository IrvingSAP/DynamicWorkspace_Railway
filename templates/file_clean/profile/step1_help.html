Ayuda — Tipo de archivo a limpiar

Fija formato, codificación y fin de línea. Sin este paso no se completa el perfil ni se publica.

← Volver al paso 1 Resumen

Para qué sirve

El tipo declara qué archivo envía el proveedor, no “el más cómodo de modelar”. Condiciona las extensiones al Ejecutar, el parser y la pantalla de campos (paso 4). Encoding y fin de línea deciden cómo se leen los bytes antes de aplicar captura, campos o reglas.

Se guarda en el borrador. Las limpiezas usan solo la versión publicada.

Qué decide este paso

ElementoEfecto en File Clean
Tipo de archivo Formato y parser. Las extensiones permitidas al subir salen de este tipo.
Codificación Cómo se interpretan los bytes. Un encoding incorrecto produce caracteres raros en los campos y reglas que no coinciden.
Fin de línea Cómo se parten las líneas (LF, CRLF, auto o secuencia propia). Si no coincide, captura y campos se desalinean.

Encoding y fin de línea

  • Use el encoding del archivo real (p. ej. latin-1 en exports antiguos, no UTF-8 “por si acaso”).
  • Windows suele enviar CRLF; Unix, LF. Auto sirve si el proveedor mezcla orígenes.
  • La secuencia personalizada solo si el catálogo lo permite y el archivo no usa un fin de línea estándar.

Si cambia el tipo a mitad de diseño

Los campos del paso 4 dependen del tipo. Si ya hay estructura y cambia de formato, esa definición puede quedar inválida. Revise el paso 4 antes de publicar. Las reglas que apuntan a campos desaparecidos quedarán huérfanas.
