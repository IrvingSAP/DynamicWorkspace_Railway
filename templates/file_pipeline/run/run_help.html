Ayuda — Ejecutar pipeline

Dispara la versión publicada (no el borrador del diseñador). El botón Ejecutar solo corre si el pipeline está Activo y usted tiene permiso.

← Ejecutar

Por qué «Ejecutar vN» aparece deshabilitado

Publicar y activar son dos cosas distintas:

  • Versión publicada (v1, v2…): snapshot inmutable del rail. Sin ella no hay qué ejecutar.
  • Estado del pipeline (En proceso / Activo / Inactivo): interruptor de operación. Un pipeline recién creado queda En proceso. Publicar no lo pone en Activo.

Si el recuadro dice El pipeline debe estar Activo para ejecutar, el PA debe pulsar Marcar como Activo (en esta pantalla o en el hub). ED/GE/CO no pueden cambiar ese estado: hay que pedírselo al administrador del pipeline.

Al pulsar el botón atenuado no se envía el archivo: aparece el mismo aviso para que revise el recuadro rojo.

Requisitos para disparar

  1. Hay una versión publicada.
  2. El pipeline está Activo (no En proceso ni Inactivo).
  3. Usted es PA, ED o GE del pipeline (CO solo consulta).
  4. Tiene permiso de ejecución en cada proyecto de paso (Clean, Gate, Pipe, …).
  5. Hay un archivo de entrada (salvo que el bloqueo anterior impida llegar a validarlo).

Qué hace la corrida

File Pipeline no parsea el archivo. Llama al runner de cada app y pasa el artifact de salida al siguiente paso. Canal de disparo desde esta pantalla: trigger_source=ui.

Si un paso falla, el resto queda omitido (on_error=stop).

Marque Vista previa (dry-run) para una corrida de prueba. Importante: no entra en el pulso del dashboard (corridas, fallidas, tasa y canales). Sí queda en el historial, con etiqueta dry-run.

Runners cableados: Clean, Gate, Split/Merge y FilePipe. Reverse, Match y Scout se rechazan hasta tener runner de orquestación.

El detalle fino (reglas, filas) sigue en el historial de cada app, enlazado por app_job_id. Tras el run puede abrir Resultado, Auditoría e Historial.
