Ayuda — Auditoría de un run

Registro de quién disparó la corrida, contra qué versión y cómo cerró cada paso.

← Volver a la auditoría

Propósito de la página

Ficha de una corrida concreta. El rail replica el snapshot publicado que se ejecutó, no el borrador actual del diseñador. CO ve metadatos de orquestación; el detalle de celdas y descargas está en cada app, según su política.

Cabecera y acciones

ElementoQué es
Franja Run Identificador, canal (ui, api, …), etiqueta dry-run si aplica, y estado de la corrida.
definición vN Versión del pipeline que se disparó.
← Historial Vuelve al listado de corridas.
Resultado Vista de cierre orientada a operación (rail OK / error / omitido), misma corrida.
Eliminar corrida Quita el registro del orquestador (no el job de cada app). Quien disparó o el PA; no si está en cola o en curso. Pide confirmación.

Bloque Disparo

CampoSignificado
CanalOrigen: UI, API, Watch, Scheduler o dependencia. Hoy el disparo desde Ejecutar es UI.
ActorUsuario o cliente que activó la corrida.
Cliente API / Idempotency / CorrelationReservados para PLATFORM_API y reintentos. En UI suelen ir vacíos (—).
IP / UAContexto del cliente, si se registró.
Triggered / Started / FinishedAlta, inicio real y cierre.
DuraciónTiempo total cuando ya terminó.
Archivo / sha256Entrada entregada al primer paso y huella del contenido.
Paso fallidoOrden del primer fallo si on_error=stop.

Rail de pasos

Nodo verde ✓ = completado, ! = fallido, – = omitido (el resto tras un stop). Cada tarjeta muestra kind, proyecto, duración, código de error o motivo de omisión, y app_job con enlace al historial nativo (PA, ED, GE).

Watch, Scheduler y API rellenarán actor e idempotency_key cuando esos canales se conecten. Esta ficha es de auditoría de orquestación, no un informe de filas de cada app.
