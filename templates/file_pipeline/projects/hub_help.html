Propósito de la página

El hub resume el pipeline {{ pipeline.name }} y da acceso a cada etapa: diseñar el rail, publicar una versión, ejecutar (si está Activo) y consultar el historial. File Pipeline no parsea el archivo: llama a los runners de las apps de cada paso.

Quién: cualquier miembro (o UF de compañía si es público) ve el hub; PA gestiona miembros y el estado Activo; PA y ED diseñan y publican; PA, ED y GE ejecutan.

Ciclo de vida (stepper)

Visual, igual que File Gate: verde + ✓ = completado; verde + número = acción inmediata; gris = aún no toca.

FasePasoPara qué sirveCuándo marca ✓
Definición 1 Diseñar pasos Rail de kinds + proyectos publicados de la misma compañía. Borrador guardado con al menos un paso válido.
Definición 2 Publicar Congela el snapshot (vN). El diseñador queda abierto para vN+1. Existe versión publicada. Si Diseñar no está listo: aviso No puede publicar. Pasos no completados: Diseñar pasos.
Ejecución 3 Ejecutar Dispara la versión publicada (UI). Requiere estado Activo y permiso en cada proyecto de paso. Hay al menos una corrida (incluida dry-run).
Ejecución 4 Historial Auditoría de disparo y pasos. Borrar un registro también lo quita del dashboard. Hay al menos una corrida (nunca se pinta como «siguiente»).

Publicar ≠ Activo. La versión es el snapshot; el estado es el interruptor de operación. Ejemplo: diseñó y publicó v1 → stepper en Ejecutar (verde 3); PA marca Activo → puede subir archivo.
